# 路线与范围

## 1.0

目标是独立、轻量、可解释、可纠正的通用记忆组件。支持明确的用户/项目/任务主体，以及可选关系状态；库、HTTP/MCP 和接入示例围绕同一核心。

1.0 整合早期关系模块与 0.6–0.9 的内部开发范围：

- 通用记忆：六种类型、结构化值、独立寿命、来源和明确替代。
- 检索：明确主体与筛选、本地词法排序、预算上下文、解释与实际使用确认。
- 时间/存储：生效与获知时间、有限版本、修订冲突、JSON/内存/自定义存储、选择性搬运。
- 受控学习：有期限候选、审阅与原子接纳、宿主抽取器、有限新字段策略、带条件的任务经验。
- 可选关系：真实互动、额度/衰减、可纠正标签、熟悉程度/信任和风格统计。
- 接入：Node/TypeScript、HTTP、MCP、审阅 CLI、平台解析器、通用模型桥和可选框架桥。
- 示例：个人/项目/学习机制示例、社群/陪伴/客服/NPC 演示、配方与参数说明。

详细能力与用途见 [首页](../README.md)、[用途与选型](use-cases.md) 和 [1.0 发布说明](releases/1.0.0.md)。

## 验收原则

功能实现、可复现问题修复、公开类型、生命周期/边界测试、迁移、打包安装与跨系统检查均是发布关卡。当前底层加固基线已完成 Windows 六组合、Ubuntu 五组合以及实际进程中断检查；条件见 [加固记录](1.0-HARDENING.md)。最终发布版本继续执行 CI 和包内容核对。

只报告已有证据支持的能力。真实模型准确率、实时平台长期运行或外部 benchmark 需要对应验证，不以离线示例代替。

## 后续方向

按真实使用需求选择，暂不承诺具体版本或日期：

- 先通过匿名、明确标注的实际用例改进检索和抽取评估，记录漏选、误选与纠错成本。
- 有全文召回需求后，再评估可组合的 RAG/向量接口和数据权限。
- 出现明确的长期存储、跨进程查询需求后，再评估 SQLite 等存储实现。
- 完整事件溯源需要重算、回放、恢复方面的真实要求和迁移方案，1.0 保持有限版本与可靠快照。
- 平台和框架接入优先按实际使用版本补测；历史 LlamaIndex TS 桥保持可选兼容，不进入核心依赖。

不因凑版本号引入身份自动合并、后台自主代理、云平台或空壳模块。所有改动以用途、证据、维护成本和独立实现为依据，保留来源与许可。

## 数据与隔离

核心不修改接入方应用的代码、配置、数据目录或运行方式。宿主负责授权、真值和模型调用。公开测试与示例使用合成数据；原始聊天、身份、凭据、私人快照、备份与本地协作资料不进入提交和发布包。

历史开发与复核记录保留在 0.6/0.7/0.8/0.9-AUDIT.md。来源与独立实现见 [NOTICE](../NOTICE.md)。
