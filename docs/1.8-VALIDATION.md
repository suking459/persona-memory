# 1.8 经验闭环验证

日期：2026-11-03。内部开发版本 `1.8.0-dev.0`，schema 8。未推送、未打标签、未发布 npm。上一批 1.7 完成后补齐 `recordExperience` 的 origin 转发并完成六环境针对性检查，再开始本批。

## 实现

- 新增 `src/experience-reuse.js`：经验候选、带精确版本依赖的反馈候选、条件复用判断、停用/重新启用候选。
- 模型报告与 host 断言分开，普通接纳不升级验证权限；通用模型提案伪造 value 中的 owner 标签不能计入确认反馈。
- 按 trialId 或 evidenceId 的连通组去重，明确条件集合，不将一次结果泛化；负反馈和核实的失败/混合结果要求复核。
- 停用采用同字段新版本，保留历史；普通召回、上下文和派生依赖均停止使用，重新启用不继承旧成功结论。
- 四个 Agent 工具和四个固定所有者 CLI 命令；共享来源由策略绑定附加，capture 不得提升 review；命令输入限 64 KiB 常规 UTF-8 文件。
- 读取旧 schema 1–7，拒绝将新字段降头伪装成旧格式，保持旧记录无 origin 时的指纹表达不变。

## 复现与修复

1. 首批可选 experience 字段被候选 hydrate 误当必需项，旧候选重新载入失败。改为真正可选，并将 schema 门槛传给候选 hydrate。
2. 审阅后的正式经验被旧 hydrate 分支统一拒绝。移除过时禁令，继续严格核对候选/正式记录的元数据、载入时刻、修订号和前驱。
3. 同回合更换证据后旧字段被覆盖，反馈链的去重桥丢失。反馈字段标识增加 evidenceId，保留桥接的独立记录，连通组依旧只计一次。
4. 检查停用不能仅成为反馈附注：从统一 `memoryAppliesAt` 排除停用元数据，避免通用召回继续注入停用方法。

Linux 使用 QEMU TCG 软件 CPU 仿真、测试期限倍率 10/单并发，不作为性能基准，不放宽生产接口期限；只使用合成测试数据。完整测试约 499 秒；这不是原生机器运行成本。至此本批实现及所列验证完成，可以推进 1.9。
