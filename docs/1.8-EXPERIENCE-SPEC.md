# 1.8 经验反馈与有条件复用规格
本地实现及所列多环境验证已完成；不替换已有 recordExperience，不自动执行经验中的任务。实际接口和边界见 [experience-reuse.md](experience-reuse.md)，验证证据见 [1.8-VALIDATION.md](1.8-VALIDATION.md)。未对外发布。

## 闭环
- 增加经验候选入口，使宿主抽取的 task/context/attempt/result/conditions/outcome 先进入候选，再由所有者审阅。
- capture 只能提出未核实的模型报告；带 verified 标记的 host 报告须经明确的 review 授权入口。SDK 标签仍是调用方声明，不是事件真实性认证。
- 每次使用后可以提交独立反馈候选：helped、not-helpful、failed、not-applicable。反馈必须引用当前正式经验的 id/revision，带实际 evidenceId 和 trialId。
- 反馈分 reported 与 owner-attested；后者只允许审阅权限入口明确提交，并保留 source=host。普通 memory_propose 不能靠 value 内伪造 owner-attested 标签获得可信反馈资格。
- reported 或普通候选审阅通过，都不自动变成真实任务已经验证。

## 适用条件与反例
使用调用方明确提供的条件标签进行确定性比较，不推断自然语言条件已经满足。经验的必需标签必须包含在当前条件中；反馈的条件集按精确集合匹配，避免把一次成功放大到另一环境。缺少证据或条件时给出明确的不足状态。

负面反馈只影响对应条件下的复核建议，不永久改写原经验或凭一次失败全局推翻方法。所有者可明确提出本版本经验的停用候选；接受后以同一字段的新版本停用，普通召回也排除它。停用保留原记录和依据，不能用遗忘冒充停用。更正或重新启用后重新评估，不自动复制旧版本的成功结论。

每条经验的反馈按 trialId 去重，优先使用明确的所有者确认；重复调用不能变成多次成功计数。输出计数和依据，不生成虚构准确率或世界范围置信度。

## 更正与过期
反馈使用现有 derivedFrom 指纹与有效性检查；经验被更正、遗忘、过期或依赖失效后，旧反馈不能帮助旧结论继续命中。同身份完整备份恢复保留反馈依赖；选择性导出拒绝派生反馈。单条经验的便携文本导出沿用旧安全边界，不转移宿主核实权限。

## 数据格式
正式经验元数据自 schema 5 已有，来源标签自 schema 7 已有。本节点需要候选经验元数据和未核实模型经验的明确格式支持，采用 schema 8，保持旧版本迁移和旧指纹表达兼容；新字段不能通过改低版本头部绕过验证。升级前保留旧格式备份，旧客户端不读新格式。

反馈本身使用现有 episode 记录及带版本的 JSON payload，无独立后台数据库。候选到正式记录的原子审阅、容量限制和跨进程 CAS 继续沿用既有实现。

## 验收
多语言原文；模型报告不冒充 host 验证；回合重复去重；条件改变不泛化；正负证据同时存在需复核；伪造 value 标记无效；私人或跨项目引用拒绝；更正/过期/遗忘后的反馈失效；明确退休保留历史；重启、共享来源、角色权限、备份恢复及旧 schema 迁移。先 SDK/CLI/MCP，再按实际可得环境验证宿主，不把协议测试充实测。
