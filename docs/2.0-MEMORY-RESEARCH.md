# Long-term Agent memory: research and host review

Research date: 2026-11-13. Baseline: local commit `0342837a89802f149e5cda0e8f091376750cae95`, version 2.0.0-dev.0. This document records inspected primary papers and vendor documentation, not replicated paper results or new host acceptance. Repository prose is English; memory data remains multilingual.

## Product identity

persona-memory is a host-independent, external memory component. Its JavaScript/TypeScript SDK embeds in an application. Its scoped MCP stdio service runs as a separate local process that an Agent calls. Owner CLI commands provide inspection/review/recovery; a local HTTP entry serves other application languages with their own identity and authorization layer. Vendor connector/configuration bundles package those entry points.

A skill can explain when to recall, propose, correct and confirm use. It cannot replace persistence, scoped access, revision checks or owner review. A vendor-native plugin can wrap the component, but the core is neither a replacement Agent nor a model modification. Installing a package alone does not make an arbitrary host call its tools.

Distinguish four layers:

1. Model parameters encode training; this project does not retrain the model.
2. Working context and conversation compaction serve an active conversation.
3. External durable memory stores selected records for future sessions.
4. Authoritative project instructions and permission policy remain separate from recalled data.

## Papers inspected

The versions below pin the methods actually inspected. Original publication years are not claims about today's commercial products. Suggestions in the last column are our adaptations, not features automatically supplied by a paper.

| Primary source | Mechanism and limitation | Practical adaptation |
| --- | --- | --- |
| [MemGPT, 2310.08560v2](https://arxiv.org/html/2310.08560v2), 2023/2024 | Manage a limited working context with external recall/archives and explicit memory functions. Paging does not make the underlying context window infinite. | Keep a compact standing briefing, retrieve details on demand, and bound calls, results and budgets. Existing handoffs/SDK/MCP cover parts of this design. |
| [Generative Agents, 2304.03442v2](https://arxiv.org/html/2304.03442v2), 2023 | Relevance, recency and importance select memories; reflection builds higher-level inferences. The target is believable simulation, not verified business facts. | Treat reflection as a sourced proposal with conditions and review. Do not make an LLM importance score authority or let repeated recall establish truth. |
| [LoCoMo, 2402.17753v1](https://arxiv.org/html/2402.17753v1), 2024; [ACL paper](https://aclanthology.org/2024.acl-long.747/) | Evaluate long conversations, temporal events, multi-hop questions and adversarial/unanswerable cases. Retrieval and final answer quality are different measurements. | Use independently authored multi-session traces and explicit evidence sets. Preserve abstention and distractor cases. No benchmark dialogues or answers are imported. |
| [LongMemEval, 2410.10813v2](https://arxiv.org/html/2410.10813v2), 2024/2025 | Separates indexing, retrieval and reading; evaluates extraction, multi-session/temporal reasoning, updates and abstention. | Add stage-specific evaluation. Report complete evidence coverage and rendered-context coverage, not just one successful hit. Scripted capture is not measured extraction. |
| [A-Mem, 2502.12110v1](https://arxiv.org/html/2502.12110v1), 2025; [NeurIPS publication](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html) | Atomic notes, generated semantic metadata, links and evolving organization. Autonomous rewrites can change the interpretation of old material. | Prefer small sourced records and explicit dependencies. New summaries/links require review; a full automatically evolving knowledge graph is deferred. |
| [Mem0, 2504.19413v1](https://arxiv.org/html/2504.19413v1), 2025 | Extract salient candidates, compare with existing memory and select add/update/delete/no-op; a graph variant is separate. | Keep extraction separate from authorization. Reuse existing proposal/revision/conflict mechanisms; an inferred contradiction must not silently delete history. No SDK or graph database is imported. |
| [LightMem, 2510.18866v4](https://arxiv.org/html/2510.18866v4), revised 2026 | Filter/compress input, organize topics and move consolidation away from online inference. Topic mixing and batch size affect quality. | Plan explicit, bounded consolidation batches with cancellation and review. Keep costly processing outside the synchronous request path; no daemon or compression model is enabled by default. |
| [SimpleMem, 2601.02553v1](https://arxiv.org/html/2601.02553v1), 2026 preprint | Self-contained facts, resolved references/time, multi-view indexing and query-aware retrieval/consolidation. | Preserve source/time/subject alongside normalized claims. Measure lexical, metadata and optional semantic paths independently. Never guess ambiguous identities or dates during core storage. |
| [Beyond Similarity / MemGate, 2606.06054v1](https://arxiv.org/html/2606.06054v1), 2026 preprint | Semantically related memories may still be inappropriate for a task; studies a learned admission gate and memory-induced behavior risks. | Apply scope/validity before ranking; retain data-only framing and host permission checks. Add task-admission negative cases. No trained gate, weights or safety-effect claim is imported. |
| [Agent Memory as Recommendation, 2610.34673v1](https://arxiv.org/html/2610.34673v1), 2026 preprint | Treats selection as a budgeted evidence-set problem. Complete candidate pools, ranking and final packing contribute separately; assumptions about independence/monotonic utility matter. | Score whether all required evidence survives retrieval and rendering. Use budget/limit controls. A trained ranker and this paper's reported gains are not assumed to transfer. |

Ten papers are listed, including two evaluation papers. Their public design ideas are reusable inputs to an independent implementation. None of their source code, prompts, weights or datasets was copied into the project. Any later import needs a separate component/data license check; an arXiv license is not a blanket software license.

## Findings for 2.0

The current project already has strong storage/revision/review/scope/expiry/dependency mechanisms. Its development gap is demonstrating useful selection and host behavior, not merely adding another database or storing more text. Native memories also make duplicate ownership a practical integration risk.

The independent synthetic baseline now separates required lifecycle behavior from capability challenges. It exposes missing complete evidence under small limits/budgets, unmeasured cross-language/paraphrase retrieval, and omission of standing constraints when the current task has no lexical overlap. These are different issues and require different remedies; two are deliberate capacity controls rather than runtime defects.

Concrete uptake, exclusions and acceptance gates are recorded in [the research adoption plan](2.0-RESEARCH-ADOPTION.md). Evaluation usage and results are in [the evaluation guide](long-term-evaluation.md). Paper results, download counts, source tests, synthetic mechanism cases and real host/model outcomes must remain separate evidence layers.
