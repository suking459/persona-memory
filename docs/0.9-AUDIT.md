## Reproduced fixes

Eleven review cases included ten first-failing cases and nine causes:

1. Null candidates incorrectly became an empty collection.
2. Acceptance options.id overrode the explicit target.
3. Imported candidates bypassed the 30-day review deadline.
4. Accepted candidate/formal references lacked cross-collection validation.
5. Zero candidate-byte capacity rejected valid empty snapshots.
6. Batch array accessors could execute during validation.
7. Extractor subjects were compared before strict descriptor validation.
8. Experience condition-array accessors could execute.
9. Timer-only leases let synchronous slow extraction/model callbacks exceed deadlines and still succeed; monotonic post-callback checks now prevent candidate/use commits.

Initial eight failures: `before-fix.txt`; two extra deadline failures: `deadline-before-fix.txt`. Full regression/matrix passed after fixes. Tests do not prove arbitrary synchronous code can be forcibly interrupted on one JS thread.

## Remaining gate and limits at that time

No usable Linux environment had yet been available (WSL inventory failed; Docker absent), so Linux remained a real 1.0 gate, later addressed in [hardening](1.0-HARDENING.md). No live-model extraction accuracy, answer quality or full LongMemEval score was measured. External callbacks/stores require cooperative cancellation; returned results are deadline-checked. Deduplication/history are finite. SQLite, graph databases, automatic identity merge, event sourcing and scheduling were outside this batch. Failed persistence keeps local edits; verification is a host report, not independent proof.

No source/tag/Release/npm publication or QQA integration/change occurred. See the [1.0 gate](1.0-CANDIDATE.md).
