# 1.0 候选范围与最终发布关卡

日期：2026-10-29。功能范围已齐，当前仍是本地开发候选。package.json 的 0.4.0 保留既有源码基线；不是已经发布 1.0。当前分支 work/1.0-development，后续不再增加凑版本号的功能，优先修复实测问题和完成剩余验证。

## 范围冻结

- 独立 Node 核心、零运行时依赖；用户/项目/任务主体、六种通用记忆、可选关系状态。
- 明确来源、证据、纠错、有限版本、生效/获知时间；字段更新的 replaceId/expectedRevision 与存储级 CAS 各自负责一层冲突。
- 明确范围的有界检索、完整上下文预算、解释/省略、按真实调用确认使用。
- 候选审阅、宿主受限抽取、默认关闭的有限接纳策略、带条件的宿主任务经验。
- 原有平台/框架桥、HTTP/MCP、轻量 CLI、例子、合成评估、迁移与删除。
- schema 5 为本候选格式：候选独立集合，经验确认是正式 episode 的独立元数据；支持 1/2/3/4 迁移。

不加入完整事件溯源、SQLite、自动身份合并、后台自主代理、任务执行引擎、云平台或完整文档 RAG。它们需要真实需求和独立验证，不是为了达到 1.0 而强制添加。

## 默认值和兼容

maxMemories=10000、maxVersionsPerMemory=32；state 默认 48 小时、episode 默认 90 天。候选默认 72 小时、1000 条、4 MiB，上限同时受字节约束。详细硬边界见 typed-memory.md、retrieval.md、time-storage.md、learning.md。

旧同步 ingest/putMemory/buildContext 等使用方式保留；纯异步存储使用显式 open/persist/reload。预览是纯读取，使用确认不提高证据真实性。status=current 指版本头，当前事实按区间读取。旧代码会拒绝 schema 5；回退恢复升级前备份，不能直接改版本号。

已有原型对象字段、过大 JSON/批次、旧修订、错误作用域、坏磁盘文件、过期候选和迟到结果会明确失败，不静默丢数据或覆盖新纠错。完整删除覆盖候选、保留版本与内部派生引用；宿主外部另存的材料仍由宿主管理。
