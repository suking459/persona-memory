# 0.7 local acceptance and review

Historical record, 2026-10-29. Started after 0.6 passed; 0.8 had not started. This was an internal batch, not a public release.

## Delivery

Explicit user/project/task retrieval with kind/key/source/evidence-time filters; bounded lexical ranking and optional host-precomputed relevance; candidate/text-work caps; complete JSON context with character/token budgets; successful-use confirmation without evidence renewal; atomic overlap-deduplicated context confirmation; vendor-independent model bridge with retry/deadline/cancellation/late-result protection; HTTP management-gated writes and MCP reads.

## Reproduced corrections

Eight added audit cases first failed, then passed after correcting seven causes:

1. Version queries split into digits and 1.0 could match 2.0; preserve query identifiers separately from stored-field tokenization.
2. Generic bridge dropped constructor `now`; forward it explicitly.
3. Combined confirmation lacked aggregate bounds; enforce 64 records / 32 subjects before counting.
4. An unconsumed stream counted as completion; reject/request cancellation and require final consumption.
5. The final tokenizer result could exceed budget, including empty content; recheck both context paths.
6. Whitespace variants of turn IDs used different execution caches but one usage ID; normalize before execution and reject invalid IDs early.
7. Caller input mutation while awaiting could acknowledge a different turn; capture identity at invocation.

The large-context character accumulator was also bounded without repeatedly recounting the whole output. Before-fix logs: `.artifacts/0.7-audit/{before-fix,stream-before-fix,budget-turn-before-fix,input-before-fix}.txt`.

## Boundaries

Lexical relevance is not semantic understanding or confidence. Empty results and work caps do not prove all data was checked. Budgets cover individual memory blocks; hosts own total input and permission roles. No real-model quality comparison or current-source cross-environment matrix was completed here. Old CI did not replace that gate. Temporal storage and candidate learning were still future batches. No QQA change, real-chat access, push, tag, Release or npm publication occurred.
