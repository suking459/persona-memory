# 0.7 本地验收与复核

日期：2026-10-29。上一批 0.6 通过复核后开始此批次；本轮没有进入 0.8。0.7 为内部开发批次，不是新增公开版本。

## 本批次交付

- 用户/项目/任务的明确范围检索，类型/字段/来源/观察时间过滤。
- 本地字面排序、命中词与原因；可选宿主预先提供相关度，不强制任何模型或向量库。
- 候选数量与总文本处理量上限；无匹配返回空，工作量截断明确报告。
- 完整 JSON 记忆上下文、联合字符/token 预算、省略原因。
- 只在宿主成功使用后确认；确认不刷新事实证据、有效期或修订。
- 多个通用块及同一 chat 的关系块可原子确认，重叠记录只计一次。
- 不绑定模型厂商的调用桥，保留重试、超时、取消与迟到结果保护。
- HTTP 通用记忆读写（写入仍需管理开关）、MCP 读取工具及机制示例。

## 复核发现并修复

针对开发中的实现，先记录失败，再修复并保留回归：

1. 版本号查询被拆成数字片段，导致 1.0 误命中 2.0。查询保留完整标识，存储侧的字段拆词与查询策略分开。
2. 通用桥丢失构造参数 now，已经改为明确传递。
3. 组合确认没有限制合计记录/主体，已在任何计数前限制为 64 个记录、32 个主体。
4. 尚未消费的流对象被当成完成响应；现拒绝并请求取消，要求宿主消费到完成后返回最终结果。
5. 最后一次 tokenizer 结果没有再次约束，空内容也可能超预算；新旧上下文入口都执行最终检查。
6. 带首尾空白的轮次标识使用不同执行缓存，却落到同一使用记录；执行前统一规范，并提前拒绝非法标识。
7. 等待模型期间调用方复用并修改输入对象，可能把确认记到其他轮次；调用开始时捕获原始标识。

对应 8 项补充审计用例均已先复现失败再修复。日志在本地 .artifacts/0.7-audit/before-fix.txt、stream-before-fix.txt、budget-turn-before-fix.txt、input-before-fix.txt。

同时优化了大内容的字符预算累计，避免反复对整个已组装上下文重新计数。

## 结论与边界

本轮本机验收通过；未保留上述已复现问题，不作“绝无 bug”保证。

当前默认检索是有界字面策略，不是通用语义理解或事实真伪判断。相关度不是可信概率。空结果可能是没有字面命中；工作量截断时也不表示检查了全部内容。外部相关度必须由宿主自己计算并管理权限。

字符/token 预算覆盖单个记忆块，不覆盖整次模型输入。固定约束可通过显式类型过滤另建块，宿主检查省略与总预算后再调用模型。资料不能自行获得执行权限。

真实模型质量对照和最新修订的跨环境/Node 支持矩阵尚未完成；旧 0.4 CI 不作为此批次证据。0.8 的时间版本/存储互通、0.9 的候选学习仍未实现。

所有变更留在本项目。没有修改 QQA、读取真实聊天、推送代码、创建标签/Release 或发布 npm。完整 1.0 仍按约定统一验收和发布。
