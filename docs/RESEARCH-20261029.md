# Research and implementation choices

Historical research, 2026-10-29. Primary project documentation/papers were preferred. This is use-case analysis, not market share or user-volume research.

The day's GitHub API snapshot recorded Mem0 67997 stars, Graphiti 32307 and Letta 25273. These reflect open-source attention only, not paid demand, active users or this project's market size. Repositories: [Mem0](https://github.com/mem0ai/mem0), [Graphiti](https://github.com/getzep/graphiti), [Letta](https://github.com/letta-ai/letta).

| Primary reference | Design signal | Local choice |
| --- | --- | --- |
| [Mem0 update](https://docs.mem0.ai/core-concepts/memory-operations/update) | Update and verify memories as requirements change | Explicit correction and source state, retaining lightweight local policy |
| [Zep facts](https://help.getzep.com/facts) | Separate known/effective/invalid time; timestamps do not prove truth | Independent evidence/expiry; use counts are not fresh evidence |
| [Letta memory](https://docs.letta.com/configuration/memory) | Inspect/edit memory and context growth | Diagnostics/budgets without an autonomous background memory agent |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | Extraction, cross-session, time, update and abstention evaluation | Deterministic update/invalidation/isolation/empty-evidence tests |

The full LongMemEval benchmark was not run; no comparable QA score is claimed. Real demand still requires external trial. Competitor graph databases/background agents alone do not justify copying their infrastructure.

Priorities: inspectable evidence and correction, omit irrelevant/uncertain content, bound abnormal input/retries/late commits, then expand useful applications without excessive infrastructure.

Actual fixes: many unmatched quotes exceeded a 1.5-second subprocess bound; a single scan reduced the whole subprocess to roughly hundreds of milliseconds including startup, not a precise pure-function benchmark. Callback deadlines/cancellation bound waiting while ignored cancellation continues occupying capacity. Explicit visitor/profile/snapshot caps preserve old valid files on oversized writes. Lifecycle selection avoids repeated array deletion. Implementations were authored in this project; historical concepts/default-parameter provenance remains recorded.
