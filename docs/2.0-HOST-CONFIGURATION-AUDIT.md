## Correction from this review

The DSH MCP client documents service namespaces of 1–32 ASCII letters/digits/underscore/hyphen. Our internal configuration helper already restricts names to a conservative lowercase/underscore subset but previously accepted up to 64 characters for every host. The DSH profile now rejects names above 32 before emitting configuration. Tests cover 32 accepted, 33 rejected and the helper's independent 64-character bound for Codex. Default private/shared generated names already fit the DSH bound; the current bundle API does not expose arbitrary custom service names.

No host configuration, trust setting, account, model subscription or daily credentials were changed. Project trust remains the host owner's decision. WorkBuddy's import bundle is not certified for marketplace submission. A local desktop MCP configuration entry does not prove desktop UI execution.

## Actual acceptance boundary

[The 1.5 acceptance report](AGENT-ACCEPTANCE.md) records real-model tests for specific Windows Codex CLI and DSH headless versions. It does not certify the new 1.6–2.0 tools, another version, another OS, or another vendor. Current source tests exercise library behavior, generated bundles, actual local MCP subprocesses and owner commands. All other vendor profiles remain experimental until tested in the intended installation.

The server negotiates the four MCP versions listed in adapters/agent/server.js; unknown requested versions receive its supported version rather than an invented claim of supporting a newer specification. Vendor clients must accept the negotiated version.

These mutable documentation links were inspected on the date above. They are not vendor endorsements or a guarantee that future clients retain the same configuration.
