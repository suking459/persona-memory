# 1.5 independent-policy specification

Date: 2026-11-02; pre-implementation baseline `abe05719f2f5656f549b9f72cce600f1db245a2f`. The owner wanted to minimize third-party code/notice burden, without removing required notices or promising worldwide originality. This specification preceded the implementation commit; chronology alone does not prove originality.

## Behavioral contract

Keep typed records/candidates/review/correction/forgetting/MCP/Agent/JSON/SQLite/schema 6 operational without deleting existing data. Remove default emotion/health/good-news lists, tag-advice sentences and relationship tones. TAG_RULES becomes an immutable empty collection; explicit extraRules retain quote/negation/subject guards.

Score only structured mention/reply/direct interaction or bounded host affinityDelta. Explicit zero stays zero; both signs obey per-message caps, positives obey the daily allowance, self messages never score. Text does not establish health/personality/emotion facts. Preserve 0–100 and five numeric thresholds for compatibility, with band-0…band-4 and empty hints; disclose historical parameters rather than claiming concept invention. Legacy praise/insult/pat default to zero. Reasons use stable direct/mention/reply/host codes; ordinary-talk quota applies to direct interaction, and candidate access gains no review privilege.

Retain style storage count/totalChars/questions/emojis/night/catch and public summaries. New candidates use Unicode words rather than 2–4-character windows, at most once/word/message, scanning 4096 UTF-16 units and retaining at most 128 distinct valid words. Keep block lists/capacity; statistics are not personality findings.

## Tag state specification

normalizeTag accepts compatible rows, returns null without a tag, uses finite timestamps/counts with explicit fallbacks, removes expiry for long-term tags and preserves provenance/evidence/revision/promotion/advice data. hitTag returns a new collection, updates only the first same-name row with fresh hit/evidence/advice and short-term expiry, or creates one; inputs are not mutated.

sweepTags handles at most 4096 rows through bounded classification: expire short-term rows; downgrade long-term rows after evidence idleness; promote eligible short-term rows using compatible age/use thresholds; otherwise discard overused short-term rows. Preserve expired/promoted/demoted/forcedOut counters. Capacity prefers long-term rows, then recent evidence/hits and stable original order; validate limits and avoid repeated deletion loops.

Unknown-source demo advice in synthetic fixtures is replaced with newly authored text and documented post-processing. Existing user-snapshot advice is not erased, and processed fixtures are not claimed byte-identical to originals.

## Validation and attribution boundary

First test default non-inference, explicit scoring, custom rules, legacy import and bounded lifecycle; then full multi-environment regression. Compare all distribution code/necessary tests using hashes, snippets, normalized identifiers and AST candidates, with manual uniqueness/history review rather than copyright percentages. Record implementation origins/commits. Prior exposure to old code means this is not a separate-team clean-room claim.

Retain current notices while preparing exact LICENSE/NOTICE/README/package proposals with deletions, retained material, basis, risks and applicable versions; apply only after explicit owner approval. Project MIT cannot override unknown third-party obligations. Dependencies/framework rights stay theirs. Do not republish/retag v1.0.0 or retroactively revoke rights.
