# 1.5 独立策略替换规格

日期：2026-11-02；实施前基线 abe05719f2f5656f549b9f72cce600f1db245a2f。用户要求尽可能消除第三方代码及声明负担；这不是授权误删必须保留的声明或宣称全网原创。本规格先于本批代码提交，记录实现需求，不把提交时间本身当作原创证明。

## 行为要求

- 正式记录、候选、审阅、更正、遗忘、MCP/Agent、JSON/SQLite 和 schema 6 继续工作，不因来源整改而迁移删除已有数据。
- 不再内置情绪/健康/喜讯等关键词表、标签建议句或亲疏口吻。TAG_RULES 为只读空集合；extraRules 仍为用户显式提供的字面规则，保留引号、否定和主体筛选的现有边界。
- 关系分仅接受结构化交互标记（提及、引用、明确指向），或宿主明确提供的有限 affinityDelta。显式 0 应保持 0，不因普通文本另加分；负值与正值均受单条上限限制。isSelf 不记分。文本不决定情绪、人格或健康事实。
- 保存 0–100 数值与五段阈值用于兼容旧数值消费者；段标识使用 band-0 至 band-4，hint 为空。阈值、额度、衰减等作为兼容参数公开说明其历史，不冒充概念首创。旧 praise/insult/pat 分值字段只作类型兼容，默认 0，不恢复文本推断。
- 关系计分 reasons 改为 direct / mention / reply / host 等稳定代码。普通交互日额度只针对 direct，宿主明确给分仍遵循总正分日额度。模型候选不因此取得审阅权限。
- 风格统计保留 count/totalChars/questions/emojis/night/catch 的存储形状和公开摘要。新短语候选来自 Unicode 分词后的词，不再从 2–4 字滑窗猜片段；每条消息每词至多计一次，扫描至多 4096 UTF-16 单元、128 个不同有效词。保留用户屏蔽词与现有总容量限制；不把统计当作人格判断。
- 标签规范化和生命周期按下述状态规格重新实现。API 字段名和持久化形状为兼容契约，不以重命名降低相似度。

## 标签状态规格

normalizeTag 接受既有标签记录：无标签返回 null；时刻与计数用有限值及明确回落；长期标签不设过期时刻；保留来源、证据编号、修订与晋升时刻，不改写 advice 的用户数据。

hitTag 返回新集合：同名项只更新首次匹配项的命中、证据时刻和建议，短期项延期；没有同名项才创建。不得修改传入数组或对象。

sweepTags 对最多 4096 条输入执行有限分类：先移除已过期的短期项；长期项按证据闲置期限降级；短期项按兼容的有效使用次数和存续时间晋升；其余短期项达到使用上限即淘汰。保留 expired/promoted/demoted/forcedOut 计数语义，容量选择优先长期项，再按最近证据/命中时间及原次序稳定截断。上限参数必须合法，不能靠循环反复删除。

旧快照中的建议文本属于输入数据，不擅自清空；测试夹具中来源未决的演示建议改为新写的合成文本，并准确记录后处理，不能继续声称夹具字节完全未经改动。

## 验证与来源边界

1. 先检查默认不再推断、宿主明示分值、自定义规则、旧数据导入及有界生命周期，再完整多环境回归。
2. 对全部拟分发生产代码与必要测试做哈希、片段、标识符归一化和 AST 候选比对，结合历史和表达独特性人工复核；不以百分比断言著作权归属。
3. 新增模块记录实现来源和开发提交。已看过旧代码，不能把本批称为隔离团队意义的 clean-room；可以记录按独立需求重写及其比对结果。
