## 复现后修复的问题

| 问题 | 原行为 | 修复 |
|---|---|---|
| Unicode 键顺序 | 语言排序把不同写法的键视作相等，同内容、不同插入顺序的重试误报冲突 | 采用确定的字符串全序，保留不同键，不依赖运行环境的语言 |
| 已过期编号被复用 | 旧版本仍引用已清理编号，重新绑定到其他记录后，库生成的快照可能无法恢复 | 仍被引用的编号继续保留，复用明确冲突；导入时校验缺失节点的字段、修订、前后关系与时间一致性 |
| 用已清理编号忘记记忆 | 存在相邻版本引用时仍返回未删除，留下旧内容 | 通过保留引用定位逻辑字段，删除其所有保留版本和对应摘要 |
| 特殊形式的记录集合 | getter 被调用、隐藏条目或 Symbol 键被丢弃，可能改变导入内容 | 检查自身属性描述；遇到这些输入在修改状态前拒绝，不执行 getter |

## 明确的边界

编号幂等性不是永久操作日志。记录与其引用都已被清理后，不再保留该编号的去重信息；新观察应使用新的唯一编号，重试应有期限。

forgetMemory 对无法识别的编号返回 removed=0，不应把它当作“整个历史已经删除”的证明。若编号及所有直接引用都已清理，但已知 subject/kind/key，可先按该逻辑字段列出 includeInactive=true 的保留版本，再忘记任一返回 ID。该路径也有回归测试。需要整个主体清理时使用 deleteSubject。
