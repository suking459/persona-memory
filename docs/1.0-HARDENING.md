## Emulation and harness

TCG is CPU emulation. Early harness failures involved Node 18 internal reads hitting monkeypatches, callbacks not starting before tiny deadlines, and process startup consuming watchdog budgets. Restore ordering/start allowances were fixed without deleting assertions. PM_TEST_TIMEOUT_SCALE (1–20) and PM_TEST_CONCURRENCY (1–64) are development-only. Final Linux used 10 / 1; Windows used defaults. Production modules do not read these settings and no API deadline/input/storage limit was relaxed.

Linux actually ran FIFO, link and read-only-directory checks (three additional tests), with no skips. Reproduce using npm ci --ignore-scripts --no-audit --no-fund, then PM_TEST_TIMEOUT_SCALE=10 PM_TEST_CONCURRENCY=1 npm test, typecheck and the three evaluation scripts. Node 18 uses the explicit test:core list with serial execution. Historical CI setup was not presented as a newly triggered remote run.

## Fixes and regression evidence

22 public regressions plus three Linux filesystem cases were added. `.artifacts/platform-audit` retains failures, final logs and manifests.

- Strict UTF-8 fails on disk/HTTP/MCP/review CLI instead of silently converting bytes to another valid identifier; original state/files remain.
- Actual reads are capped at maxBytes+1 despite file growth; regular-file checks before/after open reject links/FIFO/devices and avoid blocking pipe opens.
- Cleanup owns only successfully exclusively created temporaries; collisions preserve other files. A vanished lock after a completed commit does not fabricate ENOENT failure.
- Bounded JSON copying executes no getters/toJSON, counts all fields including unknown ones, caps encoded bytes/depth 32/nodes 2,000,000 and is shared by import/async reload. Failures do not replace state or leave busy stuck.
- Own-data dictionaries support identifiers named toString/valueOf/hasOwnProperty/__defineGetter__ without inherited-function access across ingestion/tags/visitors/use/maintenance/deletion/reload/dimensions.
- Candidate storage remains separate even if formal maxMemories=0; acceptance then fails atomically against actual formal capacity.
- Every local HTTP route checks loopback Host/actual port before data access; Origin/admin/Bearer retain separate roles. Deterministic forged-Host tests were not represented as a real-browser attack exercise.
- MCP serial handling waits for stdout drain and propagates input backpressure; pending input is capped at 1 MiB and complete EOF JSON need not end with a newline.

Existing deadlines/late results/cancellation/recursion/retries/capacity/seeded replay/version/deletion/migration/two-writer checks remained intact. Constraints were not removed to get passing results.

Node 26 --disable-proto=throw core passed 267/267. Permission-mode tests used synthetic project directories: memory store worked, out-of-bound reads failed and JSON persistence explicitly returned ERR_ACCESS_DENIED with cleanup when fsync was unavailable. It did not skip fsync to claim success. See [filesystem permissions](https://nodejs.org/api/permissions.html#file-system-permissions) and [permission model limits](https://nodejs.org/api/permissions.html).

## Abrupt exits and limits

Actual writers were SIGKILLed before rename and immediately after it; new readers saw complete old/new JSON respectively. Leftover locks caused ERR_STORE_LOCKED and required explicit recovery, no stealing/retry loop. Windows six runtimes: 12/12; Linux five: 10/10; total 22/22. Process termination does not establish power-loss/controller/directory-metadata/network-filesystem safety. Link/Host checks do not replace host directory permissions/identity authorization.

No macOS/ARM, network-drive, real extraction quality or long-running live Discord certification. No QQA chat reading/change. Core remained dependency-free and required attribution was retained. Final frozen digest: `f6baa71aa4f86e42c146200c32648bbbff9b36cd8ce81c5f00ec0401af75abce`. All six Windows/five Linux combinations had zero failures/skips, with types/evaluations/install/kill checks. This was bounded evidence, not a guarantee of no unknown vulnerabilities. Release metadata/publication remained a subsequent unified 1.0 step.
