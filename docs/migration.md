# 从已发布 0.3.0 迁移

目标为 GitHub 源码 0.4.0，npm 发布独立处理。

1. 停止对同一个存储目录的并行写入，备份关系文件。
2. 以相同 persona、默认空 scope、tagScope=user 打开旧文件，核心校验并在内存迁移到 schemaVersion=3，通用记忆从空集合开始。
3. 验证档案后调用 flush；保留的原始备份由调用方管理。
4. 切换 tagScope 或 scope 需要明确迁移，不默默把跨频道标签复制到每个频道。

没有 scope 的文件仍使用原 persona.json 名称；非空 scope 使用组合摘要文件名，避免分隔符碰撞。损坏文件或未知 schema 抛错，不覆盖原文件。

## 行为变化

- buildBlock 改为纯预览。旧代码若依赖注入计数，需要改用 buildContext + confirmContext；无须计数时可继续 buildBlock。
- 机器人自己的消息完全忽略，不再改人的最后活动时间。
- 默认不从旁观夸奖/辱骂计算关系分；scoreAmbient=true 可选择旧行为。
- 普通直接互动可正确计分，talkDailyCap 与 perMessageCap 生效。
- 每日额度使用可配置时区，默认 UTC；需要中国自然日可设 Asia/Shanghai。
- 维护使用独立的衰减锚点，保留真实互动时间；旧的 lastInteractiveAt 在已发布版本中可能已被维护覆盖，无法反推出丢失的历史时间。
- 类型区分 RawStyle（内部统计输入）和 StyleProfile（摘要输出），修复之前的形状不一致。
- HTTP/框架接入保留实际发送者与显式标志，不把一条消息复制成多人的发言。

## 回滚

代码改造前的源码与文档备份位于本项目 .local-backup/20261029-before-milestone。它不包含 .git、node_modules、QQA 或原始聊天数据，也不进入发布包。

不要把 schemaVersion=3 文件交给只认识 schema 1/2 的旧代码直接写。回滚需要恢复旧代码，并使用迁移前的数据备份。恢复前先停止本项目自己的写入进程；不需要停止或修改 QQA。

源码更新与 npm 发包分别进行。公开变化见 CHANGELOG.md；本机验证记录见本地 DEVELOPMENT.md。

## 本地 1.0 稳定化中的行为收敛

包版本仍保留既有 0.4.0；本地通用记忆使用 schemaVersion=3，尚未发布新的中间版本。旧 schema 2 可以加载，新格式会阻止旧实现静默忽略通用记录。以下行为需在最终 1.0 迁移说明中保留：

- 上下文现在包含标签的完整 advice；标签和建议共同占用字符/token 预算，因此同样预算可能容纳更少的标签。不会把截断建议当作一次完整使用。
- 存在当前状态建议时不附加通用关系语气，避免情绪状态与玩笑提示冲突。affinityContext=false 可关闭关系档位/分数/语气，查询档案不受影响。
- support 默认关闭通用社交词表和关系语气。业务状态及 advice 由宿主显式设置；确需情绪/状态规则时通过 extraRules 开启。
- 简单中文规则对明确第三方、疑问和条件表达保守弃答，可能减少召回。每次只检查命中前后各 160 个 UTF-16 代码单元；不解决任意人名、指代、时态或“已经恢复”的推断。条件表达的同句后续陈述也可能被略过。
- setTag 和导入快照中的 advice 必须为字符串且不超过 2000 个 UTF-16 代码单元。不符合的快照拒绝加载并保留原文件；升级前在独立副本中整理数据，不静默截断原始内容。
- 旧使用次数不再令陈旧标签反复晋升；无新证据的长期状态降级后最终过期。档案容量上限同时覆盖宿主事件写入。

这些改动不构成通用语义理解或真实模型效果承诺。最终 1.0 候选仍需执行新的支持矩阵验证，不能沿用 0.4 基线的远程结果。


## 本地 0.8 的 schema 4

当前 export/flush 输出 schema 4，支持 schema 1/2/3 迁移。schema 3 以即时替代语义生成 validFrom/validUntil；schema 4 不可只改头部降级。旧代码会拒绝新文件，回退必须使用升级前备份。残缺链有重叠或重复修订时明确拒绝并保留磁盘原文件。详细兼容约定、默认 32 版本保留上限和示例见 [时间版本与存储](time-storage.md)。此前 schema 3 的叙述保留为 0.6/0.7 开发记录。


## 本地 0.9 / 1.0 候选的 schema 5

当前新快照为 schema 5，必须含 candidates；旧 schema 1/2/3/4 迁移后候选为空。schema 4 的生效时间保留，schema 3 仍按旧即时替代语义升级。经验验证元数据只在 schema 5 中有效，旧实现拒绝新文件；回退使用升级前备份。不要只修改头部版本。已接受候选与仍保留的正式版本会交叉检查，歧义/坏文件明确失败。见 [学习约定](learning.md)。
