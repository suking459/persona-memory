# 1.1 小版本更新计划

日期：2026-11-01；分支 work/1.1-development；本地版本 1.1.0-dev.0。用户明确纠正：当前只是现有项目的修改和补充，不按 2.0 立项。本轮不自动推送、发布或改 v1.0.0 历史。

## 这次做什么

1. 补上真实使用所缺的 Agent 接入通道：范围绑定、正式记忆读取、候选提出、审阅、更正、遗忘、持久化和重启恢复。
2. 为 Codex、DSH、Claude Code、WorkBuddy，以及 Gemini CLI、Qwen Code、Kimi Code、CodeBuddy、iFlow、VS Code Copilot、Cursor 生成各自配置；按官方契约记录验证等级。
3. 新 Agent 默认使用用户已选择的“宿主抽取＋候选审阅”，直接复用已有通用记录 API，不调用旧关系评分/情绪标签推断。
4. 继续处理来源风险，保留准确证据和声明。现有关系规则的来源未决，不把新增接口通过测试说成旧来源问题已经消失。

## 这次不扩展的内容

不改成新 Agent 执行平台，不增加数据库/向量引擎，不调整整体模块结构。此前提出的三档分档、风格统计改造和整套标签生命周期重写是过大草案，暂不应用。来源处理后续按必要的小补丁和升级验证推进；版权声明删除仍须单独展示具体差异、依据与风险，并经用户明确批准。

## 从最终使用流程验收

使用者在本机明确选择实际项目和允许的个人/项目主体，准备接入包、在宿主中启用。每个新任务按问题读取，新增事实和更正先提案；候选不是正式事实。所有者审阅，保存后重启可读取。只允许绑定范围，不与宿主原生记忆自动混写。

配置生成、MCP 协议、真实宿主是三个验收等级，分别记录。真实宿主未安装/未登录或未跑完整流程时，必须标未验证；不能把配置模板算完整适配。

不修改 DSH、Codex、QQA、WorkBuddy 的现有配置、数据或运行方式。真实联调使用独立项目/合成数据，必要的宿主变动另按用户授权操作。公开发布前完成相应多环境、迁移、安装和来源检查。

## 当前批次

专用 Agent 通道和 11 类配置生成已实现，提供显式配置应用/撤销；操作只写所有者指定的目标，本轮未对真实宿主执行。Windows 六个既有 Node 运行环境通过；类型、真实 MCP 子进程/重启、离线安装通过；Codex 已安装 CLI 在项目临时配置中解析通过。各厂商宿主端到端和本批 Linux 尚未通过，不借用 1.0 旧结果。详情见 1.1-AGENT-BATCH.md 与 agent-integration.md。

后续接入流程批次补充独立 inspect 列表/详情、只读接纳预检及长连接的持久化刷新；修复独立审阅后旧缓存/下一次写入冲突。多语言作为横向要求持续验证，详见 1.1-REVIEW-FLOW-BATCH.md 与 1.1-MULTILINGUAL-BATCH.md。整批仍不表示所有厂商已完成端到端。
