# 1.1 incremental update plan

Historical plan, 2026-11-01; work/1.1-development, 1.1.0-dev.0. The owner clarified that this was incremental improvement, not an immediate 2.0 rewrite. No automatic push/publication or v1.0.0 history change.

Scope: a real-use Agent channel with fixed subjects, approved reads, proposals, review, correction, forgetting, persistence and restart; generated Codex, DSH, Claude Code, WorkBuddy, Gemini CLI, Qwen Code, Kimi Code, CodeBuddy, iFlow, VS Code Copilot and Cursor configurations; host extraction plus candidate review rather than old social inference; separate evidence-based handling of unresolved historical origins.

The batch did not become an Agent execution platform or add a database/vector engine/architecture replacement. Larger tier/style/lifecycle proposals were deferred. Notice removal still required a concrete diff, evidence/risk disclosure and owner approval.

Acceptance starts from the user flow: choose a project/allowed subjects, prepare and enable a bundle, recall at task start, propose new facts/corrections, review independently, persist and read after restart. Pending claims are not approved facts and host-native memory remains separate. Configuration generation, MCP protocol tests and real host/model tasks are three distinct evidence levels. Untested hosts remain explicitly unverified.

Daily DSH/Codex/QQA/WorkBuddy configuration/data were not changed. Real integration uses isolated projects/synthetic data and separately authorized host actions. Multi-environment/migration/install/origin checks precede publication.

The first Agent/configuration batch passed six Windows runtimes, types, actual MCP subprocess/restart and offline install; isolated Codex CLI parsed configuration, without model acceptance. Linux/real hosts were not certified by older 1.0 results. Later review-flow work added independent inspection, acceptance preflight and per-call refresh after owner edits. See [Agent batch](1.1-AGENT-BATCH.md), [multilingual batch](1.1-MULTILINGUAL-BATCH.md) and [review flow](1.1-REVIEW-FLOW-BATCH.md).
