# 1.5 release-candidate checklist

Historical checklist, 2026-11-02; then-local 1.5.0-dev.0. This checklist did not authorize pushes, tags, historical changes or npm publication. Later explicit release approval is recorded separately.

| Gate | Requirement |
| --- | --- |
| User flow | Bundle-local owner.mjs/OPERATIONS.md covering install, proposals, correction, forgetting, disable and recovery |
| Regression | Final frozen Windows/Linux source, not a previous batch's results |
| Installed package | Same tarball offline on both systems; generated owner paths, recovery, guarded apply/undo and private-file exclusion |
| Real hosts | Exact Windows Codex CLI/DSH headless five-case model results in the acceptance matrix; owner CLI tests do not certify desktop UI |
| Other vendors | Nine generated profiles remain experimental; no demand to install/subscribe to all products without a support promise |
| Languages | Original-language storage, locale and retrieval tests; localized guidance/English fallback; no universal understanding claim |
| Semantic services | Optional; no default network/model download or invented real-quality gains |
| Origin/notices | Bounded replacement/review complete; exact notice diff still required approval; unresolved history disclosed |
| Data/recovery | No chats, credentials, bindings, private audits/backups/test logs; back up before schema 6 and roll back with old code/data |
| Compatibility | Disclose changed defaults/bands; internal milestone numbering does not establish a compatible minor release |
| Publication | Owner decides version/scope only after reviewable evidence |

Keep promises bounded. A desktop entry requires separately authorized enablement and actual host validation; completing a milestone does not expand public support automatically.
