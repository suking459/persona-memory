## 已实现

1. 派生来源：derivedFrom 指定同一主体的正式记录 ID/修订；服务端计算内容及逻辑字段指纹。正常读取、检索、上下文、经验和有效时间查询检查来源，变更、过期或丢失时不再把旧归纳当现行资料。
2. 有上限的传递检查：最多 16 个直接来源、深度 8、128 个不同记录和固定步骤上限；循环与跨主体引用拒绝。未来版本生效前仍按旧区间工作，来源的保留期限限制派生记录期限。
3. 遗忘影响预览和级联：清理逻辑字段及依赖它的派生字段历史、相关候选；保留其他主体。即使来源连续更新并裁剪多个旧版本，逻辑字段指纹仍能找到旧副本。只能追踪明确登记的引用，不能声称自动找到所有手工复制语句。
4. 候选质量提示：相同字段的相同值、不同建议值、现有值和来源变化；提示有上限，不自动合并、不凭置信度判真。不同 key 的语义矛盾不作假识别，由宿主/所有者复核。
5. assertion 区分明确陈述、观察、推断和外部报告。新 Agent 缺省标为推断；标签、候选接纳和证据编号都不等于独立验证。源类别仍由服务端约束，模型不能借标签变成 host 或获得审阅权。
6. 宿主抽取、Agent 提案和独立 inspect 同步支持这些字段和提示；多语言原文保持不变。

## 发现并修复的问题

初版仅按来源旧 ID 寻找遗忘副本，在连续两次裁剪后漏掉派生记录。先保存 pruned-privacy-before.log，再改用逻辑字段指纹，加入多次裁剪的回归。

审查旧本地检查点发现：直接 SDK 输入的 kind/source 嵌套对象可能在类型校验前进入候选身份哈希，触发 toJSON。现在先校验字段，再构建身份；对照证据 hash-callback-proof.json：旧版触发 1 次，新版 0 次。它是直接 JavaScript SDK 的输入边界，不应夸大成 JSON 网络输入可以执行函数。

## 格式和迁移

当前快照写 schema 6，验证后读取 1–5。打开旧文件不自动改写。旧读取器不能使用升级后的文件，真实升级前须停写并备份。

便携记录有 assertion 时使用格式 2，否则保持格式 1；旧格式不得夹带新标签。便携格式不能保留派生图，因此明确拒绝直接导出派生记录；完整快照保留来源关系。旧快照及用户原文不会被自动删除。
