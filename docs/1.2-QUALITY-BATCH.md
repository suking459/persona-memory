# 1.2 write quality and correction loop

Historical local 1.2.0-dev.0, unpublished. Started after reviewing 1.1's Windows 371 baseline/digest and saving local checkpoint 0fb3426. Owner authorization allowed autonomous progression to 1.3 after review.

## Implementation

- derivedFrom references approved same-subject IDs/revisions; the server computes content/logical-slot fingerprints. Default reads, retrieval, context, experience and time queries reject changed/expired/missing sources.
- Bounded transitive checks: 16 direct sources, depth 8, 128 distinct records and fixed steps. Cycles/cross-subject references fail. Prior effective intervals remain valid until scheduled transitions; source expiry bounds derived expiry.
- Forget previews/cascades remove the logical field, dependent field history and related candidates, preserving other subjects. Slot fingerprints retain linkage after repeated source-version pruning. Unregistered manually copied text cannot be tracked automatically.
- Bounded same/different proposed/current-value hints assist review without automatic merging/truth decisions or invented cross-key semantic contradiction detection.
- assertion labels explicit/observed/inferred/external; Agent defaults to inferred. Labels, approval and evidence IDs do not authenticate truth or raise source/access privileges.
- Learner, Agent and independent inspect support these fields while preserving source language.

## Reproduced fixes

ID-only forgetting missed derivatives after two consecutive prunes. Preserve `pruned-privacy-before.log`, then use logical-slot fingerprints and repeated-prune regression. Earlier SDK code also allowed nested kind/source objects into identity hashing before type checks, potentially invoking toJSON. Validate first; `hash-callback-proof.json` records old=1/new=0 invocation. This is a direct JS SDK boundary, not JSON network code execution.

Schema 6 reads validated 1–5 without automatically rewriting old files. Old clients cannot read upgraded files; stop writers/back up first. Portable assertion data uses version 2, otherwise version 1; old formats reject new labels. Derived graphs require full backup or explicit re-derivation, not lossy selective export.
