# 1.4 storage, backup and migration

Historical local 1.4.0-dev.0, unpublished. Started after 1.3 Windows 454 / Linux 457, types/install passed and checkpoint 59df4f8 was saved.

Optional built-in SQLite adds no runtime dependency; it loads only when selected and requires Node 22.13+. Node 18/20 keep JSON. Sync/async snapshot interfaces use real transactions, CAS, immediate lock refusal, identity/strict-schema checks and per-operation connection closure. Foreign databases/unexpected schema or journal mode/links/devices fail; no lock stealing/retries.

Full logical backup preserves original text/dependencies, verifies SHA-256 and old-schema migration, and previews replacement counts for ten minutes. Apply rechecks source checksum, target content/revision/configuration and final CAS. Failed writes do not replace memory early. Local edits made while awaiting async commit remain visible with an explicit committed/reload-required receipt. CLI backup/restore and identity-from preserve logical identity across paths/machines without inheriting review permission by default. Configuration, inspect/review and actual MCP support selected SQLite.

Targeted SQLite tests reproduced synchronous flush passing internal optional undefined log fields into strict JSON. Export now performs bounded descriptor-safe copying, omits only optional internal undefined properties under JSON rules, invokes no user callbacks, and feeds flush the validated snapshot. Full regressions preceded source freezing/matrix.

Windows link tests used directory junctions where file-symlink permission was absent; Linux tested actual file symlinks. Abrupt pre-commit child exit is not a power-loss guarantee.
