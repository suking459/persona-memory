# 1.9 local measurement and bounded maintenance specification

Design only; implementation starts after final 1.8 review and same-source cross-environment validation. Memory counts, injection counts and model self-scores do not prove benefit. Provide reviewable local on/off comparisons and bounded upkeep across hosts.

## Measurement

No default observer, timing loop, network, file output or telemetry. Hosts explicitly provide scalar measurements or invoke a bounded local operation. A fixed-capacity in-memory sample ring accepts only fixed operation names, finite duration, success/failure, byte counts and actually measured token counts. Missing tokens are unknown, not character-derived estimates; do not invent prices or savings.

Do not retain bodies, queries, memory values, evidence links, user identifiers, arbitrary error messages or tool arguments. Avoid timing wrappers around arbitrary asynchronous callbacks that can hang or mutate late. Paired comparisons use explicit numeric case indices and on/off mode, one completed measurement per mode. Operator-supplied external experiment records identify the host/model/configuration/data origin; synthetic mechanism tests are not real-model gains.

Report measured outcome/time/bytes/token differences; missing either side remains unknown. Do not pair different cases or invent accuracy, statistical significance or universal improvement.

## Bounded maintenance

Separate owner preview/apply, no background loop. Explicit subject, at most 32 targets/call, bounded scans and cascade impact. Eligible objects: expired candidates and actually expired/effective current field heads. An expired historical version must never trigger forgetting a later valid field; skip future heads or still-usable records.

Preview exact counts and bounded ID samples for history/derived/candidate impact. Skip any target whose cascade would touch a still-usable record, including a corrected descendant with an obsolete historical dependency. Stage the full result in a draft, then reuse management's full-snapshot CAS commit. State/configuration/time/access/target changes require a fresh preview; never half-delete a batch.

Do not clean external/system files, backups or unknown data. Maintenance is not a default user-forgetting policy.

## Acceptance

Getters/invalid numbers/oversize input; fixed capacity/no body retention; duplicate/unpaired experiments; missing tokens/failed tasks; expired plans; scope/shared roles; CAS races; usable descendants/future heads/old expired versions; atomic persistence failure; Windows/Linux and supported Node. Separate library mechanism, protocol and actual host/model outcomes.
