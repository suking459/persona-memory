# persona-memory 1.5 本地候选说明

日期：2026-11-01。当前包版本 1.5.0-dev.0，仅本地开发候选；本轮未推送 GitHub、创建标签/Release 或发布 npm。v1.0.0 的标签、源码和版权文件保留。

## 已具备的增量能力

| 内部节点 | 已实现 | 实际用途 |
|---|---|---|
| 1.1 | 固定范围 Agent 通道、默认候选/独立审阅、配置生成/撤销、Unicode 与语言选项 | 在不同 Agent 中使用项目事实、个人偏好；范围与宿主权限保持明确 |
| 1.2 | 派生来源引用、更正失效、连带遗忘、重复/竞争候选提示、断言类别 | 改掉错误来源后，不再从旧摘要里捞出同一错误 |
| 1.3 | 可选语义召回、Ollama / OpenAI-compatible 嵌入、限时取消与词法回退 | 对明确选择的服务做同义/跨语言检索，失败仍可用本地检索 |
| 1.4 | 可选 SQLite、CAS/事务、完整校验备份、恢复预览与逻辑身份迁移 | 多写者拒绝静默覆盖；更换目录/电脑/存储后保留历史与来源引用 |
| 1.5 | 只读 doctor、召回解释、批量审阅预览、连带删除预览 | 所有者能看清现状和影响，再明确接受、拒绝或删除 |

这是给宿主加记忆能力的库与接入通道。任务执行、权限批准和模型推理仍由宿主负责；它不会自动接管电脑、保证模型事实正确或把所有聊天都保存下来。

## 全球语言支持的实际边界

结构化值、证据及备份保留原始语言；Unicode 检索、规范化、组合字符、不同语言大小写、无空格语言分词及多语言路径已有合成测试。locale 可按连接或单次查询指定。中英接入/工作流说明已经提供，其他语言的说明目前主要回落英文。

不把这些机制测试称作全球所有语言的理解认证。跨语言语义效果取决于所选嵌入模型；本轮仅测接口/人工向量与标注的合成问题，没有真实模型质量分数。新增功能可用于编程项目、客服知识、个人偏好、任务记录、游戏/NPC 等场景；它们不是某个平台聊天插件的专属规则。

## 本地使用与升级

- 核心仍为零运行时依赖；JSON 支持 Node 18+。内置 SQLite 仅在明确选择时加载，需 Node 22.13+；不自动安装数据库或模型。
- 当前新命令需本地源码或本地打包候选，不能使用公开 npm 1.0.0 获取。先看 [中英接入](agent-integration.md) / [English integration](agent-integration.en.md)。
- 日常操作保持“读取正式记忆 → 有证据的候选 → 独立所有者审阅 → 更正/遗忘 → 重启复核”。[所有者管理](owner-management.md) 展示排错、解释与批量/删除预览。
- 新快照使用 schema 6，读取 1–5 会验证并在内存规范化；只读打开不直接改写原文件。写入新 schema 后不应直接交给 1.0 读取；回退使用升级前的可信备份。
- [备份恢复](storage-backup.md) 是全量替换。预览十分钟过期；目标版本、内容、配置或备份变化都要求重新预览。备份/审阅计划含私人数据，须保密，不能随项目发布。
