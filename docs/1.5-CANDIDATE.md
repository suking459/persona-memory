# 1.5 local candidate

Historical candidate record, 2026-11-01, with later policy/operations evidence appended before publication. At this checkpoint package 1.5.0-dev.0 was local; v1.0.0 source/tag/notices were preserved. Later stable release approval is recorded in [release notes](RELEASE-1.5.0.md).

| Milestone | Added capability | Purpose |
| --- | --- | --- |
| 1.1 | Scoped Agent entry, capture/review, config/undo, language options | Use project facts/preferences across explicit host boundaries |
| 1.2 | Dependencies, invalidation, cascading forget, quality hints, assertion labels | Correct sources without continuing to recall stale summaries |
| 1.3 | Optional bounded embedding recall and lexical fallback | Explicit service-based semantic retrieval with safe failure |
| 1.4 | Optional SQLite, CAS/transactions, backup/restore/identity migration | Avoid silent stale overwrites and preserve logical identity |
| 1.5 | Doctor, explanation, batch review/deletion previews | Owners inspect state and impact before applying changes |

The component does not take over a computer, execute tasks, verify all model facts or save all chat. Unicode/original-language values/evidence/backups, locale matching, marks, no-space segmentation and multilingual paths have synthetic tests. They are not certification of all languages. Cross-language semantic quality depends on the selected embedding model and was not measured with real models in this batch.

Core is dependency-free; JSON supports Node 18+, optional SQLite requires 22.13+. At this historical checkpoint new commands required the local candidate, not npm 1.0.0. Use approved reads → evidence-linked proposals → separate review → correction/forget → restart verification. Schema 6 reads 1–5 after validation without rewriting on read. Full restore replaces data and requires a fresh ten-minute plan after any source/target/config change. Private backups/plans must not be published.

Final independent-policy evidence: Windows Node 18 core 516; Node 20 full 525; four modern full combinations 540 each. Ubuntu 24.04.5 x64 / Node 26.13.0 emulation full 543 plus types; zero failures/skips/cancellations. Digest `8f5893f09b9fd1c4f36679dea1c7c38c87870d3f885e37eff37e02c9881fd69a`. Twenty newly authored explicit-rule cases and retrieval/learning evaluations are mechanism tests, not real-model accuracy or zero-defect guarantees. Install checks consume the same batch tarball; earlier management/operations results retain their own source boundaries.

Specific Windows Codex CLI/DSH headless had five real-model cases each; nine other profiles and desktop UI remained experimental. No real semantic quality score, macOS/ARM/universal-host assurance or worldwide originality/title guarantee. The review covered 88 production files and bounded source snapshots; the unknown historical plugin chain remained unresolved. At this checkpoint the four-file notice diff was only prepared and needed approval. Private data exclusion and actual package/source checks remained gates.

The candidate recommendation was to retain local status until notice diff, release version/compatibility and promised-host evidence were approved. Breaking 1.0 defaults needed explicit version disclosure; an internal '1.5' label alone did not imply SemVer compatibility. No automatic release or progression beyond then-authorized 1.5 was implied. Later authorization superseded that historical boundary.
