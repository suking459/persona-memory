# 1.7 显式共享与贡献来源设计（已实现，本地验收通过）
基线：1.6 任务交接正在完成跨环境验证。实现与边界以 1.7-VALIDATION.md 和 sharing.md 为准；没有新增真实宿主模型认证。

## 使用流程
所有者先建立专用共享空间，再为每个宿主/贡献者生成单独绑定，显式选择 read / capture / review。私人通道继续独立；共享空间不从私人库默认复制内容。若要迁入项目知识，沿用明确 subject 映射、预览、审阅的选择性迁移流程。

一个共享空间限定一个 project/task subject，禁止 user subject；专用 namespace 和存储位置中不能混入个人记录。共享的事实仍通过候选与所有者审阅。贡献者不是自然人自动识别，身份由所有者明确分配。

## 本地权限
权限清单由所有者维护，模型工具无法新增/修改授权。每次调用重新检查授权；停用/过期/撤销后活动连接拒绝读取和修改，不使用旧缓存。读权限不能通过参数变成提案或审阅。对于拥有同一系统文件权限的程序，不宣传进程沙箱或文件级机密隔离。

共享通道作为额外 MCP 服务接入，保留私有服务；服务名必须独立，避免覆盖现有 persona_memory 配置。为未完成真实宿主验收的客户端继续注明边界。

首批只支持明确本地部署；不自动开放 HTTP、公网同步或多租户服务，不以校验和当身份认证。远程认证、TLS、会话撤销属于单独设计和验证范围。

## 贡献来源
正式保存贡献者 id、host、space 标识；由共享连接的所有者绑定附加，工具调用参数不能伪造。普通 SDK 来源标签仍是调用方声明，不宣传为外部身份认证。旧记录来源缺失保持未知，不补造历史。

候选到正式记忆需保留来源，替换时来源随新记录更新；派生指纹覆盖来源元数据。新增持久字段采用明确 schema 升级，验证 schema 2–6 的迁移与旧版本回退限制，不能静默塞入旧结构。

## 验收
- 独立私有/共享通道并存，默认无个人数据迁入。
- 两个贡献者读取同一批准项目事实；capture 提案独立审阅。
- 来源不能从工具参数注入，记录跨重启保留。
- 活动会话撤权、过期或策略损坏时立即拒绝，无旧缓存成功响应。
- 读/提案/审阅分离；跨空间、跨项目、跨身份拒绝。
- 真实多进程修改冲突拒绝，不无限重试，不丢失另一贡献者已保存结果。
- 升级、备份、迁移、恢复和来源指纹完整回归。
