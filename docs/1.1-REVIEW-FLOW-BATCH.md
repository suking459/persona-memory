# 1.1 owner review and running-session refresh

Historical record, 2026-11-01; work/1.1-development, 1.1.0-dev.0, unpublished. The 351-test multilingual baseline/digest passed first. No v1.0.0/history/notice change.

## Reproduction and fix

After capture proposed a candidate and another process accepted it, the original session still returned zero approved records and its next proposal raised ERR_AGENT_STORE. Startup-only caching missed normal independent review. Evidence: `.artifacts/1.1-review-flow/before.json` (expectedMatches=1, actualMatches=0, nextProposal=ERR_AGENT_STORE), plus baseline.log. Restart-only tests had missed this workflow. Owners also lacked binding-scoped independent candidate inspection.

Every Agent call now reads/checks storage. Independent review/correction/forget becomes visible on the next call, without a watcher/push service. `reload({ifChanged:true})` preserves state/context/import previews only when clean and revision-identical; changed storage fully reloads and invalidates old previews. Default reload semantics remain. Dirty edits are not discarded, refresh failures issue no cached answer and disable the connection until inspection/restart, and write races still fail CAS without automatic merge/retry.

Independent inspect defaults to pending, includes expiry, returns at most 32 summaries/page without value bodies and rejects stale cursors. Details show source text, proposed value and latest formal head; bounded preflight checks stale/expired/capacity conditions without mutation. Heads may be future or expired. acceptance.allowed is a temporary precondition, not owner approval; evidenceVerified remains false. CLI escapes bidi controls while JSON retains original values. No schema/runtime dependency or external-host change.
