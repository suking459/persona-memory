# 1.1 独立审阅与运行中 Agent 衔接

日期：2026-11-01。本地 work/1.1-development，版本 1.1.0-dev.0。未发布、未推送，不改 v1.0.0 历史或版权。多语言批次的受测代码摘要和完整 351 项基线先复核通过，再开始本批。

## 复现的问题

已运行的 capture 连接提出候选后，另一进程接受该候选；原连接仍返回 0 条正式记忆，下一次提案返回 ERR_AGENT_STORE。问题是连接只保留启动时的快照，并不会看到独立所有者提交。原来的“关闭再启动后可以读取”测试没有覆盖这一日常流程。

修复前证据：.artifacts/1.1-review-flow/before.json（expectedMatches=1，actualMatches=0，nextProposal=ERR_AGENT_STORE）及 baseline.log。

另一个使用缺口：只有接受/拒绝命令，没有围绕 binding 的独立候选查看命令，所有者容易依赖 Agent 转述 ID 和内容。

## 改动与行为

- 新 Agent 每次调用先读取/检查持久化快照。独立审阅、更正、遗忘在下一次调用可见；不是后台监听或实时推送。
- reload({ifChanged:true}) 只在本地干净且持久化令牌未变化时保留现有状态、待确认上下文和导入预览。存储变化则完整重载并使旧上下文失效；默认 reload() 行为不变。
- 未保存的内存更改不会自动丢弃或写回；刷新失败不给旧缓存答复，停用当前连接直至检查并重启。刷新与保存之间的其他写者仍由原 CAS 拒绝，不自动重试或合并。
- 新 inspect 命令按 binding 和明确 scope 独立查看候选。列表默认 pending，带过期标记，最多 32 条/页；游标失效明确要求重新列出。摘要不展示值正文。
- 单条详情展示原文、已提交版本头和建议值；同一套有上限的接纳预检检查陈旧、过期、容量等条件，不提交任何更改。版本头可能尚未生效或已过期，仍需核对时间。
- acceptance.allowed 是检查时的条件，不是人类批准；evidenceVerified=false 明确说明证据编号尚未经本库核实。所有者仍核对原始来源并明确运行 review。
- CLI 转义可能改变视觉方向的控制符，JSON 解析后保留原值。中英文说明同步。

实现：src/memory.js、adapters/agent/session.js、adapters/agent/review.js、tools/connect.mjs 及公开类型。未增加运行时依赖，未改快照 schema，未修改其他宿主。

## 仍然存在的边界

这是独立协议客户端和所有者命令的真实进程验证，不是 Codex/DSH/Claude Code/WorkBuddy 内部的模型任务。真实厂商宿主仍须逐项启用和端到端核验；没有因此改动它们的配置或读取账户。

每次工具调用都有快照读取/哈希/校验成本，适合当前有上限的本地文件存储，不宣称等同数据库事务。自定义存储必须让 revision 标识内容；内容变化后不能返回相同令牌。并发分页不是固定快照，预览和批准之间仍可能变化，正式接纳继续检查修订与原字段前提。

macOS/ARM 尚未验证。来源风险和必要版权仍按独立证据处理；本批不完成版权清理。当前仍为 1.1 开发中，不提前进入 1.2 或自动发布。详见 [接入说明](agent-integration.md)、[English guide](agent-integration.en.md)、[九点路线](1.0-2.0-ROADMAP.md)。
