# 1.1 multilingual foundation review

Historical record, 2026-11-01; work/1.1-development, 1.1.0-dev.0, unpublished. v1.0.0 unchanged. Unicode storage alone was not adequate multilingual retrieval.

## Reproduced changes

Thai `ฉันชอบกาแฟดำ` queried with `กาแฟ` previously missed; runtime dictionary segmentation fixed it. Bengali `কফি` versus `কফ` previously produced a false second match; vowel signs are now preserved. Hindi `कॉफ़ी` no longer loses marks and recalls the unrelated fixture. Explicit Turkish locale now supports case mapping and locale-aware stop words.

src/locale.js validates BCP 47, bounds Segmenter cache to 16 and offers English/Chinese headers. Retrieval normalizes matching without rewriting storage. Binding/call/CLI accept explicit locale; old bindings default to English. Null/invalid locale fails rather than silently disappearing, and locale never broadens scope/access. Review also fixed a dropped locale in the generic model bridge, using Turkish recall and English-header tests. Legacy typed MCP declares locale; HTTP shares core validation.

Generated instructions had English/Chinese variants and English onboarding. No runtime dependencies, automatic translation or new paid model calls were introduced.

## Limits and follow-up

No automatic translation, universal morphology/mark matching or cross-language semantics. Other instruction locales fall back to English. At this checkpoint older social/demo presentation remained Chinese-oriented. ICU/Segmenter builds need actual testing; Linux/macOS/ARM were not inherited from old-source results. No vendor E2E, external settings/chat/credential access or notice cleanup was claimed. Later [review-flow validation](1.1-REVIEW-FLOW-BATCH.md) covered this code in Ubuntu/Node 26 complete 374 plus types; the original Windows table remains historical.

References: [ECMA-402 Intl.Segmenter](https://tc39.es/ecma402/#sec-intl.segmenter), [Unicode boundaries](https://unicode.org/reports/tr29/). Actual Node/ICU behavior, not the latest standard alone, determines compatibility.
