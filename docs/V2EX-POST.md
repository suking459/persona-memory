## 正文（复制下面全部，含空行）

```
先说清楚：好感度系统不新，GitHub 上已经有做得比我深的。

etherfunlab/eros-engine 用六轴向量（warmth/patience/trust/intrigue/intimacy/tension），有 decay、有 tier drop，模型比我这套单值精细得多。koishi-plugin-chatluna-affinity 给 Koishi 生态提供了好感度/关系变量。suis077/dsh-companion 在 DSH 里做了人设卡 + 好感度。

这三个我都看过。它们的共同点：绑在某个平台或运行时里，而且循环里都要调模型。

我遇到的是另外两个问题。

一、状态需要过期，但习惯不该过期

半年前有人说过一句"最近在找工作"，这话被存下来，半年后机器人还拿它当上下文。但"他爱说确实"这种习惯，聊久了就该沉淀下来。

所以做了标签的两级生命周期：48 小时过期，重复命中是顺延不是重来；注入过 6 轮 + 存活 3 天 + 命中 2 次，才晋升成长期标签。

二、多人场景下提示词会被关系信息撑爆

一个群三十个人，如果每个人都塞一段关系描述，上下文直接没了。

所以有硬预算：最多 4 人 / 700 字，按好感度排序截断。

好感度这块我是单值模型，比 eros-engine 粗糙。好处是纯本地规则算，不调模型——群里三十个人，每条消息调一次模型评估情绪，成本比聊天本身还高。

代码抽成了零依赖的库，能塞进任何宿主：

https://github.com/suking459/persona-memory

npm 上也有：npm i persona-memory

想讨论的是那套数值（30 分日上限、2 分/天衰减、48 小时 TTL）——拍脑袋定的，跑了一个 QQ 群几个月感觉还行，但没什么理论依据。做过类似东西的朋友欢迎说说你们的参数怎么定的。
```

## 如果需要回复模板

**问：和 eros-engine 什么区别？**

答：它更精细（六轴 vs 单值），但它是个引擎、要 LLM judge、绑自己的世界观。我这个是能塞进任何宿主的库，纯规则、零成本。不冲突，想要精度用 eros，想要轻量用这个。

**问：为什么不学 eros 用 LLM 打分？**

答：因为贵，而且不稳定。同一句话今天打 3 分明天打 5 分，关系就变成随机游走了。本地规则至少是确定的。

**问：会不会让 AI 变谄媚？**

答：会，如果不设上限。所以有每日涨分封顶 + 档位提示词（每个档位写清了该用什么语气、不该答应什么）。好感度高不等于有求必应。

**问：数值有依据吗？**

答：没有，就是跑出来试的。这也是发出来的原因，想看看别人用什么参数。
