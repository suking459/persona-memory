## 已实现

- 明确 observedAt/createdAt 与 validFrom/validUntil；未来版本按区间切换，支持独立 knownAt 的有限历史查询。
- expectedRevision 前置条件、默认 32/最高 1000 版本保留，拒绝重叠/歧义链与旧写覆盖。
- 默认 JSON 的独占锁、内容修订 CAS、临时写入和重命名；显式异步 SnapshotStore、MemorySnapshotStore、JsonFileStore、open/persist/reload。
- 按明确主体导出当前值，显式映射、差异预览和整批导入；类型、示例、HTTP/MCP 与异步模型桥接。
- schema 4 输出，旧 schema 1/2/3 迁移与旧写者拒绝。详细契约见 [时间与存储](time-storage.md)。

## 复核发现与修正

新增 8 项深入复核用例中，正确对准超时错误码后的修复前运行有 6 项实现失败、2 项通过，修复后全部通过：

1. 两个以上相邻版本被裁剪时，断开的残留链可能有重叠生效区间。现按整个字段的保留版本检查区间、修订和获知顺序。
2. 只把 schema 4 头部改成 3，会静默丢失未来生效语义。旧格式带新时间字段现明确拒绝。
3. 最新版本过期被删除而旧片段还在时，重新写入可能错误地重启 revision=1。现在要求显式清理残留历史。
4. 断开链可能包含重复修订或相互矛盾的缺失编号。现跨保留片段和缺口身份一并校验。
5. 仅限制预览数量不足以限制内存。现加总约 8 MiB 预览池字节上限和大库导入工作量边界。
6. forget 一个尚未正式导入的 ID 不会释放待导入值。现在删除类入口清理待导入计划。

基础验收也修正了纯异步存储维护时误调同步 flush、删除空主体后仍保留导入预览的问题。超时测试曾因断言使用“timeout”而实际消息为 deadline 失败，这是测试断言问题，已改用 ERR_TURN_TIMEOUT；不计为实现 bug。

## 剩余边界

- 本批未执行新的 Windows/Linux × 支持 Node 版本完整矩阵；此前 CI 是旧修订证据。当前结果不能替代最终 1.0 跨环境关卡。
- 未接实时模型、QQA 或原始聊天，没有线上答案质量、LongMemEval 或生产吞吐量结论。
- JSON 锁/CAS 只覆盖遵守协议的本项目本地文件写者；网络盘、旧代码、不遵守锁的程序和断电恢复未获完整验证。异常退出可能保留锁，不自动抢占。
- 异步外部存储必须自行原子 CAS、超时和取消；核心不自动合并、不循环重试，也不声称数据库事务。内存修改与存储提交分开。
- 有限版本和 TTL 会产生历史缺口。任意回填/分叉合并、SQLite、完整事件溯源与 0.9 候选学习未实现。
- 选择性格式只搬运导出时当前值，不同步未来计划、完整历史或权限；宿主负责映射与访问检查。

没有推送分支、创建标签/Release、发布 npm，或改动 QQA/其他应用。公开包版本保持既有 0.4.0；继续以完整 1.0 验收后统一发布为约定。
