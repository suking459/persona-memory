Historical record, 2026-10-29. Local batch accepted, unpublished; 0.9 not started. The 162-test 0.7 baseline was reviewed/backed up first.

## Fixes

After correcting the timeout-code assertion, eight deep-review cases had six implementation failures and two passes before fixes; all passed afterwards:

1. Pruning adjacent nodes could leave overlapping detached intervals; validate entire retained slot chronology/revisions.
2. Lowering a schema 4 header to 3 lost future semantics; reject new fields under old formats.
3. Expired latest-head removal could incorrectly restart revision 1; require explicit cleanup of incomplete history.
4. Detached fragments could contain duplicate revisions/contradictory missing IDs; validate gap identity across fragments.
5. Plan count alone did not bound memory; add approximately 8 MiB pool and import-work limits.
6. Forgetting an uncommitted imported ID retained its pending values; deletion clears affected plans.

Also fixed synchronous flush during async-store maintenance and retained plans after empty-subject deletion. A test expecting message text 'timeout' instead of 'deadline' was corrected to `ERR_TURN_TIMEOUT`; it was not counted as a product defect.

## Limits

No fresh complete Windows/Linux × Node matrix or live model/QQA/chat/LongMemEval/performance evaluation ran here. JSON CAS protects cooperative local writers, not arbitrary network filesystems/old programs/power loss. Leftover locks need explicit recovery. External stores own atomic CAS, timeout and cancellation; no automatic merge/retry or database transaction is promised. Memory commit differs from persistence.

Finite versions/TTL leave gaps. Historical insertion/branch merge, SQLite, event sourcing and candidate learning were not implemented in this batch. Selective export copies current values, not future synchronization/history/permissions. No push/tag/Release/npm or external-app changes occurred; package version remained the existing 0.4.0 pending unified 1.0 release.
