# persona-memory: 1.0 to 2.0

Originally designed 2026-11-01; execution status is tracked in [ROADMAP](ROADMAP.md) and milestone reports. Milestones organize incremental work, not automatic releases or a wholesale core rewrite. The owner approved stable 1.5.0 on 2026-11-02 and continued local 1.6–2.0 work. Milestones 1.6–1.9 have current validation evidence; the local 2.0 source candidate has passed integrated Windows/Linux validation; package and publication evidence remain separately scoped.

## Release cadence

1.1–1.4 and 1.6–1.9 stay local: no per-milestone main push, public tag or npm publication. 1.5 is an optional validated midpoint; 2.0 is the next complete delivery with a separate owner publication decision. Future versions may use x.5 midpoint / next-integer complete releases. Serious defects can justify a scoped fix proposal but do not automatically override release boundaries. Notice deletion requires audit, exact diff and explicit approval.

## Cross-cutting language and isolation

Serve multilingual use rather than only Chinese. Preserve source text through storage/restart/transfer; explicit locale and Unicode literal retrieval do not prove native-language understanding. Later correction, semantics, paths/migration, handoff/sharing/experience/metrics preserve the same constraints. Repository documentation/comments/examples/default presentation are English; explicit language resources and regression fixtures remain multilingual. See [language boundaries](multilingual.md).

All work stays in this independent project. Public outputs exclude real chats/identities/credentials/private snapshots/backups/diagnostics. QQA and daily hosts are not modified merely to gather data. Generation, protocol tests and real-model host tasks have separate acceptance levels.

## Acceptance detail

**1.1:** prioritize named Codex/DSH/Claude Code/WorkBuddy, then publicly extensible Gemini CLI/Qwen/Kimi/CodeBuddy/iFlow/Copilot/Cursor as available. Model-API compatibility is not Agent integration. Each promised host needs enable → scoped read → proposal → review → correction → restart → forget → access/approval denial → native-memory coexistence. Host extraction uses candidate review, not emotion keywords for project facts. Origin independence remains ongoing; unsupported provenance is neither silently cleared nor marketed as original.

**1.2:** keep summaries/experience explicitly tied to source revisions, with finite depth/work rather than an infinite graph. Invalid sources stop current recall; forgetting cascades registered references. Same-field duplicates/competition assist review without confidence-based authority override. Do not pretend to detect arbitrary cross-key semantic contradictions. Test A→B preference updates, stale summaries, repeated retries, conflicting sources and abstention without evidence; measure actual errors rather than invent targets.

**1.3:** evaluate authorized/anonymized or labeled questions across languages, paraphrases, time, negation, scopes and empty results. Distinguish lexical mechanism from semantic quality. Keep embedding/reranking outside core, apply scope/validity first and fail visibly to lexical. Relevance cannot revive old/conflicting records. Report recall/false recall/abstention/context/time against a clear baseline; do not enable unmeasured new services by default.

**1.4:** optional storage complements existing JSON/CAS. Driver/runtime support is explicit, not universal. No retry-until-success loops. Backups include version/integrity; recovery previews and tests before replacement. Migration maps identity explicitly and excludes host credentials/config. Test real writer competition, locks, disk faults, corrupt backup, interruption, upgrade/rollback and permissions; process interruption is not power-loss durability.

**1.5:** doctor inspects bindings/version/store/candidates/dependencies without risky auto-repair. Explain selected/omitted records and scope/source/time; preview writes/deletion. CLI/MCP and optional local views serve the library rather than turning it into a website platform. Midpoint release requires the complete lifecycle, evidence for promised hosts, bounded origin findings, dependency/privacy/install/platform/upgrade/recovery checks. Support scope can be narrowed, never filled with untested templates.

**1.6:** checkpoints carry goals, confirmed/reported results, pending items, blockers, next suggestions and references. Opening rechecks time/validity/access and distinguishes reported completion from execution. Suitable for code/research/documents/learning/long-running projects; no scheduler/background tool dispatcher is added.

**1.7:** owners bind contributors across hosts explicitly; similar names are not automatically the same person. More assertions do not make a claim truer. Prefer same-machine deployments; public remote use needs separate authentication/authorization/transport/revocation design rather than relabeling legacy HTTP management as secure remote MCP.

**1.8:** go beyond existing recordExperience with actual-use feedback and counterexamples. One failure does not globally retire a method; one success does not generalize. Stale versions/environments/rules require review/invalidation. Summaries/merges enter review with sources retained. Benefits come from later comparable tasks, not memory volume or self-ratings.

**1.9 and 2.0:** compare the same host/model/task with memory on/off, distinguishing library overhead from service latency and unknown from measured token/cost data. Keep local diagnostic content minimal, no body telemetry. Maintenance is previewable, bounded and stoppable; failures permit explicit read-only/lexical/no-injection degradation. Revalidate current Windows/Linux/Node source, promised hosts, upgrades/recovery/dependencies/origins/packages and docs. Add macOS/ARM only when actual scope/evidence supports it. Reaching a version number never proves completion or authorizes publication.
