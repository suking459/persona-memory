# persona-memory：1.0 → 2.0 路线

制定日期：2026-11-01。以下是功能设计和验收安排，不表示后续节点已经实现。公开基线保留 1.0.0；本地已推进 1.5.0-dev.0 候选验收。1.1–1.4 已逐批验证，1.5 的真实宿主模型任务及历史来源收尾仍是单独发布门槛，不把功能实现等同发布许可。

## 发布节奏

- 1.1、1.2、1.3、1.4：本地内部迭代，不逐节点推 GitHub 主分支、建公开标签或发布 npm。
- 1.5：可选的中期公开发布。先整体验收；达不到门槛就顺延，不为版本号强发。
- 1.6、1.7、1.8、1.9：继续本地迭代。
- 2.0：完整范围验证后正式发布。它是下一次完整交付，不预设必须推倒核心重写。
- 后续大版本可沿用 x.5 中期更新、下一整数版本完整发布的节奏；若已发布版本出现严重问题，另提出小范围修复建议；这不是自动突破发布节奏的授权。

版本号是组织工作用的节点，不是做完就自动发布的指令。版权删除仍按用户此前要求，先审计并展示实际差异，再经明确批准。

## 多语言是横向要求

用户确认面向全球语言使用，不把项目限制在中文场景。1.1 先补原文保存/恢复、Unicode 检索、中英接入说明和显式语言选项；1.2 候选纠错按语言验证；1.3 补多语言及跨语言语义评估；1.4 覆盖 Unicode 路径与迁移；1.5 发布前完善英文安装排错及实际宿主语言流程；1.6–1.9 的交接、共享、经验和成本验收继续覆盖混合语言。语言支持按实际证据逐项声明，不把合成字面检索样例当作母语理解或全部语言认证。详见 [多语言边界](multilingual.md)。

## 九个节点总览

| 内部节点 | 主线 | 相比已有 1.0 实际增加什么 | 使用者得到什么 |
|---|---|---|---|
| 1.1 | 接入可用与来源风险收尾 | 专用范围绑定的 Agent 通道、宿主提案/审阅全流程、配置准备/安装回退、逐宿主验收；按最小范围替换确认的风险内容 | 接上工具后能读、记、改、忘、重启恢复，不靠用户自行补整个生命周期 |
| 1.2 | 写入质量和纠错闭环 | 更正后的关联结果失效、重复/矛盾提案提示、证据引用质量检查、不同可信来源的明确处理 | 改掉一条错记忆后，它不会继续从旧摘要或派生结果里冒出来 |
| 1.3 | 召回与上下文质量 | 在已有词法检索上补多语言/同义表达评估、可选语义召回接口、组合排序与去重；保留范围过滤和完整预算 | 换一种问法也更容易找对记录，减少无关内容挤占上下文 |
| 1.4 | 存储、备份和迁移 | 可选 SQLite 存储适配、受控多进程写入、备份校验/恢复演练、跨机器迁移向导 | 多 Agent 使用和更换电脑时，数据更可靠、搬运更容易 |
| 1.5 | 可检查、可解释、可管理 | 记忆 doctor、检索/写入解释、候选批量预览、迁移和删除影响预览；整合前四批的文档与实际宿主验收 | 所有者能看懂保存了什么、为何命中、哪里出问题，并安全处理；可作中期公开版 |
| 1.6 | 任务接续与交接 | 有范围的任务交接包、已完成/待办/阻碍/下一步、所需记忆清单和过期条件；跨聊天/宿主恢复上下文 | 换会话或换 Agent 继续项目，少重复解释，交接不冒充已经执行任务 |
| 1.7 | 多 Agent 共享与隔离 | 显式共享空间、贡献者/来源标识、读/提案/审阅授权、并发修改冲突提示 | 多个工具可复用已授权的项目知识，个人与其他项目内容保持隔离 |
| 1.8 | 可验证的经验复用 | 在已有经验记录上补成功/失败反馈、适用与失效条件、经验修订/淘汰、避免过度泛化的检索 | 复用经过验证的方法，也能记住“不适用于什么情况”，不把一次成功当通用真理 |
| 1.9 | 成本可见与完整候选验收 | 每轮记忆注入/调用/延迟/存储开销诊断、同任务开关对照、分层退化和有上限的维护；完成新候选的跨环境/来源/升级检查 | 看得见记忆是否带来收益、代价多少，故障时能减少能力继续工作；为 2.0 准备稳定候选 |

## 1.1：先把实际使用补齐

通道与后续 1.2–1.5 管理功能已经实现。已有专用 Agent 通道与 11 类配置生成，但真实宿主端到端尚未完成，不算“全部适配完成”。

先覆盖用户明确点名的 Codex、DSH、Claude Code、WorkBuddy，再按实际可得版本扩展 Gemini CLI、Qwen Code、Kimi Code、CodeBuddy、iFlow、VS Code Copilot、Cursor。其他厂商工具先查公开扩展能力，不把兼容其模型 API 当作已适配其 Agent。

每个声称支持的宿主应走完：启用 → 范围内读取 → 提案 → 审阅 → 更正 → 重启 → 遗忘 → 越权/拒绝审批 → 与宿主已有记忆共存。模型按上下文抽取后走候选，不用旧情绪关键词猜项目事实。

来源独立是所有后续节点的持续要求，不只一个节点“打勾”。1.5 公开前，任何残余未知来源内容必须有明确处理结论；没有证据就不删声明、不宣传全部原创。较大的分档/风格/生命周期行为改造暂不纳入本次小范围补接入。

## 1.2：已有候选审阅之外，再补内容质量

1.0 已有修订冲突和候选接受/拒绝，本节点不重复包装它们。

- 建立显式的派生引用：摘要、经验、交接包引用哪些记录与修订；不做无限递归的知识图。
- 更正/遗忘时，使依赖旧版本的派生结果失效，读取时不能把它们当现行事实。
- 相同字段的重复候选合并预览；不同 key 的语义冲突只提示，由宿主/所有者裁定，不凭模型置信度自动覆盖权威来源。
- 区分明确要求、观察事实、推断与外部系统真值；证据缺失时不硬存。

验收用例：偏好 A→B 后重新提问、摘要残留、反复重试、互相矛盾的两个来源、无答案时不制造事实。记录误写、漏写、纠错成本，不先编造准确率目标。

## 1.3：先证明召回问题，再引入更复杂检索

1.0 已有词法排序、外部相关度和预算，不将“搜索记忆”算新功能。

- 以真实授权/脱敏或人工标注的问法建立评估：不同语种与混合语种、同义改写、跨语言提问、否定、时间、范围、无相关记忆；区分字面召回与语义效果。
- 先改善词法召回与候选选择；可选 embedding/重排适配独立放在核心之外，不要求每个用户装向量库。
- 语义服务失败时退回词法；所有候选仍先过权限、范围、有效性，再排序。
- 去重、冲突和旧版本不得靠相关度高就强塞进提示。

验收记录召回、误召回、无答案处理、上下文长度和时间，并与当前 1.0/1.1 基线比较。没有实际收益则不默认启用新检索路径。

## 1.4：把保存可靠提升到使用方便

1.0 已有快照、CAS、文件锁和选择性导出，本节点做可选存储与运维体验。

SQLite 先作为可选适配器：保持核心零运行时依赖，按支持的 Node/系统决定使用内置能力或独立包；不先承诺所有平台同一驱动可用。限制重试和队列，不用“自动重试直到成功”掩盖并发冲突。

备份带版本/完整性清单；恢复前预览与试读；迁移明确项目/用户映射。跨机器迁移不等于默认云同步，不把凭据和宿主配置打进记忆包。

验收包括真实并发读写、锁超时、磁盘错误、进程中断、损坏备份、升级/回退和权限；进程中断不等于断电耐久性证明。

## 1.5：中期版本要让人能独立使用和排错

doctor 检查绑定、版本、存储权限、未审阅候选、失效引用、索引/快照一致性；不自动修复高风险数据。

查询解释回答“为什么选中/没选中”“哪个范围/来源/时间”；修改与删除先预览影响。优先完善 CLI、MCP 和可选本地审阅界面，界面只服务组件使用，不把项目转成网站平台。

中期发布门槛：前四批闭环、实际声称支持的宿主有对应证据、来源问题有结论、依赖/隐私排除与全新安装通过、受影响平台实测、旧数据升级与恢复可行。可以缩小明确支持范围，但不能用模板充实测。

## 1.6：交接任务，不替用户执行任务

交接包记录目标、最后已确认结果、未完成项、阻碍、下一步建议和所引用记忆修订。恢复时检查过期/失效/权限，说明哪些是建议、哪些已实际完成。

适用于写代码、研究、文档、学习和长期事务。任务执行仍由宿主承担；本库不新增计划执行器、后台任务或自主工具调度。

## 1.7：共享必须由所有者决定

默认隔离保持。共享空间明确谁可以读、提案、审阅；同一个自然人的跨宿主身份由所有者绑定，不自动把相似名称当同一用户。记录来源宿主和贡献者；多个工具的断言不因数量多自动变真。

优先同机/明确部署的共享，不默认做公网多租户 SaaS。若需要远程连接，认证、授权、传输和撤销必须先完成再开放，不能复用现有 HTTP 管理接口冒充安全的远程 MCP。

## 1.8：经验要能被否定和更新

1.0 已有带条件的 recordExperience，本节点不重新包装“记录成功经验”。

- 增加适用条件和反例反馈，区分宿主实际验证与模型自评。
- 使用之后记录是否帮助本次任务；一次失败不自动推翻全部经验，一次成功也不扩大到所有情况。
- 过时的依赖版本、环境或业务规则可使经验待复核/失效。
- 经验合并/总结先作为候选，保留来源，不自动删掉原始依据。

收益来自后续相近任务的对照结果，而非记忆条数、注入次数或模型自己打的高分。

## 1.9：衡量这件“装备”到底值不值

不主张全方位无副作用。以同一宿主/模型/任务做记忆开关对照，观察实际完成质量、错误、token、时间和存储，区分库内开销与模型/服务延迟。

内置默认只记录必要的本地诊断，不收集正文或遥测。维护有次数/时间/容量上限；合并、清理和过期策略可预览、可暂停，不能成为无界后台循环。异常时允许退到只读、词法或不注入记忆，错误必须可见。

2.0 发布候选重新做 Windows/Linux 和支持的 Node 检查，按实际范围增加 macOS/ARM；不能借用 1.0 的旧结果。补全部实际承诺的宿主、迁移、恢复、依赖、来源审计和说明。2.0 不因编号到了就自动视为完成。

## 设计依据与边界

参考的是公开的需求与设计方向，不复制第三方实现：

- [LangGraph memory](https://docs.langchain.com/oss/javascript/concepts/memory)：会话/长期记忆及作用域，对写入时机和任务连续性的提醒。
- [Mem0 update](https://docs.mem0.ai/core-concepts/memory-operations/update)：用户要求变化后定位、更新并验证结果。
- [Zep facts](https://help.getzep.com/facts)：区分适用时间和记录时间；时间戳不证明内容真实。
- 各宿主官方来源详见 adapters/agent/profiles.js 和 agent-integration.md。配置方式与版本随时间变化，不直接推导真实兼容性。

以上九点是本项目的取舍，不是竞品效果对本项目的背书。不设自动身份合并、强制云服务、核心强绑模型、默认付费请求或无边界后台自学习。
