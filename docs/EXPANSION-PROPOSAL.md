# 0.6–0.9 通用能力扩展提案

日期：2026-10-29。状态：用户已同意开始实施；0.6 通用记忆与 0.7 检索/上下文已在本地实现，0.8 时间/存储/迁移也已本地实现，0.9 受控学习也已本地实现。0.6–0.9 仅作内部开发批次，不改变到 1.0 再统一发布的约定。当前已修改本地运行代码；公开包版本与远端保持既有基线。

## 建议定位

把 persona-memory 的能力扩展为可嵌入应用的长期记忆与上下文组件。人的关系分数继续作为可选能力保留；新增记忆可以属于用户、项目或任务。现有 PersonaMemory 接口保留兼容，不把项目假装成 userId，也不让项目事实参与人的亲疏评分。

当前已经具备来源、宿主纠错、作用域、生命周期、有限历史、预算和诊断。这些继续复用，不算作新的版本功能。真正的缺口是有类型的记录、按问题检索、变化与迁移，以及受控积累经验。

## 建议内部批次

| 批次 | 主题 | 最小交付 | 可扩展项 |
|---|---|---|---|
| 0.6 | 通用记忆与明确主体 | 用户/项目/任务主体；偏好、事实、决定、经历等有类型的记录；独立生命周期；明确键值、来源和替代关系 | 业务自定义字段和记录类型 |
| 0.7 | 按需检索与上下文 | 按主体、类型、字段、主题和时间过滤；有界关键词排序；解释命中与省略；复用上下文预算 | 宿主提供 embedding/重排器，保留离线默认实现 |
| 0.8 | 版本、存储与记忆互通 | 当前值与有限历史；记录获知时间和生效时间；基于版本的冲突拒绝；存储接口；选择性导入导出与差异预览 | 可选 SQLite 适配器，经并发与恢复验证后再说明能力边界 |
| 0.9 | 受控学习与经验积累 | 有期限的候选记忆；接受/拒绝/修订；可插拔抽取器；由宿主报告任务过程和结果，形成带适用条件的经验 | 多语言抽取器、面向宿主的反馈策略、轻量检查工具 |

这套划分是本项目的产品判断，不是官方资料已经验证的效果结论。

## 0.6：让记忆可以表达不同的事情

建议新增稳定记录 ID、明确 subject、记录 kind、字段 key、受限 JSON value，以及来源/证据引用和时间。第一阶段主要由宿主明确写入，不依赖模型猜测。

示例：

- 用户偏好：回答简短、使用中文；由本人明确表达后，按确认的政策保留到修改或删除。
- 项目约束：只在 1.0 完整验收后发布；属于项目，不能影响其他项目。
- 当前状态：今天疲劳；可以短期失效。
- 任务决定：先完成兼容性检查；与目标、当前阶段、已完成步骤关联。
- 经历记录：某次尝试采用什么方法，宿主报告了什么结果。

临时情绪、稳定偏好、项目决定和已完成经历不能共用一个默认 TTL。长期保留仍受容量、删除和显式更新约束，不代表永久保留全部聊天。

验收：同一记录接口支持个人助手、项目助手、学习/创作工具中的至少三种用法，不增加对应场景专属核心分支；旧人的关系接口与旧快照仍能迁移使用。

## 0.7：让当前问题决定取什么记忆

现有 buildContext 主要从指定人的档案中挑选内容，缺少 query 驱动的记忆选择。新增检索先做主体与作用域过滤，再做关键词/字段/时间相关性排序。关系分不决定通用事实是否相关。

查询“发布安排”应优先取发布约束与阶段决定；查询“回答格式”应优先取表达偏好。没有匹配时返回空，不能用最近的无关条目填满预算。

默认支持结构化过滤和本地关键词；可选由宿主提供向量或重排结果。语义记忆的数据模型与向量检索是两件事，不以加入 embedding 作为通用化的前提。完整文档/文件知识库检索仍可以独立组合。

验收：记录命中 ID 与原因，过期/被替代/无权限范围内的记录不进入结果；严格遵守候选数量、处理量、字符和可选 token 预算；对同一输入给出可复现的默认排序。

## 0.8：让变化与跨应用使用有明确边界

同一事实可能有获知时间和生效时间。例如今天得知某个设置下周才启用，不能立刻把未来值当成当前值。优先支持宿主明确提供的时间和替代关系，不声称能理解任意自然语言时间。

当前值的选择遵循记录类型和宿主明确的更新策略；不能把“后来出现”直接等同于“更真实”。无法解决的冲突保留为冲突，不静默选择。历史只保留有界版本或差异；不强制把整个库改成全量事件平台。

把文件读写抽出为存储接口，保留内存/JSON 默认实现。异步存储使用明确的加载和持久化入口，不悄悄把 ingest 等同步 API 全部改成异步。保存时检查预期修订，旧副本写回应明确失败。SQLite 作为可选适配，不进入核心运行时依赖；未经验证不宣称任意多进程安全。

选择性导出明确的记录类型和主体，导入前预览新增/更新/冲突。身份与项目映射必须明确。跨应用携带格式先定义为本项目格式，不宣称行业标准。导入的经验/文本仍是资料，不能凭内容获得执行或修改宿主的权限。

验收：新旧/未来/迟到记录处理有确定结果；版本不匹配的写入不覆盖现有数据；只导出选定内容；导入冲突不会污染其他主体；删除包含相关候选和派生索引，保留边界可解释。

## 0.9：让系统能积累经验，同时能检查与纠正

抽取器可以由规则、现有宿主模型或离线程序提供。核心负责验证候选结构、范围、来源、数量和冲突。默认先提出候选，由宿主接受、拒绝或修订后才进入正式检索。宿主可配置有限的自动接纳策略，但模型输出不能自行获得更高权限。

任务/经历记录保存“背景、尝试、结果、条件”；只有宿主确认的结果才能标记为已验证。一次失败不等于永久无效，一次成功不等于普遍有效。用户纠错和业务状态变化可以让旧经验失效。

提供轻量的检查/差异视图，回答“学到了什么、依据是什么、何时改变、能否撤销”。复用现有演示或 CLI；不把大型管理网页变成主产品。

模型与抽取插件必须可禁用、有时限和工作量上限；默认不启动常驻代理、不自动调用收费服务、不反复自我总结。任务进展只是记忆资料，不扩成任务调度和执行框架。

验收：错误候选被拒绝后不进入上下文；重复候选不无限增长；基于旧修订的候选不能覆盖新纠错；明确报告不确定性；超时与失败不产生半次成功写入。通过跨会话、更新、时间与无答案弃答的连续场景评估，不能用测试条数替代真实效果结论。

## 优先级与成本

0.6 是最大的一次基础扩展，需要先决定记录格式、主体边界和快照迁移。0.7 直接影响“记忆是否有用”，应与模型设计一起验证。0.8 确保存得久、能改、能搬；0.9 再在稳定内核上加入受控学习。

核心继续保持零运行时依赖。存储、语义召回、抽取与场景策略按需接入。多语言主要通过抽取/匹配插件扩展，不能把当前中文词表包装成通用语言理解。

建议用固定输入衡量：当前事实是否选对、纠错是否生效、是否混入无关记忆、无证据是否弃答、上下文占用、处理耗时和状态增长。通用化意味着支持明确的多种记录与用途，不代表能自动理解所有行业。

## 暂缓事项

完整知识图谱、全量文档 RAG、自动身份关联、完整工作流引擎、自主常驻记忆代理和云管理平台，均不作为为了填满 0.6–0.9 的强制内容。新的平台适配器按真实接入需求增加。完整事件溯源仅在有限版本/差异无法满足重算和恢复需求时再采用。

## 一手资料与本项目推断

资料核查于 2026-10-29。下面是公开机制，不是市场份额或本项目效果证据。

- [LangGraph Memory](https://docs.langchain.com/oss/javascript/concepts/memory)：区分跨会话存储与不同记忆类型，并明确事实记忆不等于语义检索。支持我们先做数据模型、再选择检索器的取舍。
- [Mem0 Search](https://docs.mem0.ai/core-concepts/memory-operations/search)：检索结合问题、过滤、数量和阈值；支持按需选择，而不是每轮填入全部历史。
- [Mem0 Add](https://docs.mem0.ai/core-concepts/memory-operations/add) 与 [Update](https://docs.mem0.ai/core-concepts/memory-operations/update)：当前 add 文档是增量追加而不自动覆盖旧记录，显式更新仍有独立接口。不能把早期自动 ADD/UPDATE/DELETE 描述当作当前默认实现。
- [Zep Facts](https://help.getzep.com/facts)：区分获知时间与事实有效时间，且明确这些时间不证明内容真实。本项目借用时间区分的原则，不照搬图数据库。
- [Letta 当前 Memory](https://docs.letta.com/agent-sdk/memory) 与 [共享仓库](https://docs.letta.com/agent-sdk/repositories)：当前主线使用 MemFS，可检查与编辑，并提供内容版本前置条件。我们只取可检查、分层和防止旧读覆盖的思路，不复制其完整服务。
- [LongMemEval](https://arxiv.org/abs/2410.10813)：评估信息抽取、跨会话、时间、知识更新和弃答。作为验收维度参考；本项目未运行完整基准，也没有对应得分。

开发、合成数据和生成产物仅在本项目。QQA 和其他应用保持独立。仍到 1.0 统一发布，不按中间批次推送或发版。
