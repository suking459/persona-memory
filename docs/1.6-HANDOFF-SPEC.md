# 1.6 handoff specification

Internal development, unpublished. Baseline: published 1.5.0 / `db50dc7aa23227eb153f93b449f2b86b1f54ce0e`. No historical release rewrite, intermediate push or daily-host installation.

A source session selects approved ID/revision references within one authorized project/task and records a goal, reported completion, pending work, blockers and next steps. The owner can export JSON to a new session with the same binding/logical identity. The receiver reloads current storage, checks scope/identity/time/revision/fingerprint and decides what can continue. Cross-host use needs explicit identity preservation/restoration; personal/project stores are not automatically merged.

The bundle carries references/checkpoint text, not referenced values. Limits: 32 KiB, 16 references, 32 entries/list, 512 characters/entry, 2000-character goal, at most 30 days. Create/open does not mutate approved records/use counts, execute tasks or contact models/agents.

Checksum protects against accidental alteration, not author authentication or permission grants. Checkpoint assertions remain untrusted data. Changed/deleted/expired/dependency-invalid references require review; stale bodies cannot be treated as current. Foreign and missing references are unavailable without cross-scope disclosure.

SDK callers own reload/persist; the Agent channel refreshes per call. Identical restoration after deletion is not tracked as immutable history: this checks current state, not an event ledger.

Validation covers side effects, language, tampering/budgets, revisions/dependencies, scope/expiry, independent processes/files, read-only MCP and owner CLI. Actual host/model continuity needs separate evidence.
