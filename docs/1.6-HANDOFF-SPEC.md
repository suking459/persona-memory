# 1.6 任务接续规格

本地开发，未发布。基线是已发布的 1.5.0 / db50dc7aa23227eb153f93b449f2b86b1f54ce0e。本阶段不修改旧发布、不推送中间节点，也不安装到日常宿主。

实际流程：原会话在单一已授权 project/task 范围选择正式记忆的 ID/revision，写目标、已报告完成、待办、阻碍和下一步；所有者可导出 JSON，交给同一绑定/逻辑身份下的新会话。接收方重新打开当前库，校验范围、身份、期限、修订和内容指纹，再决定继续哪些工作。跨宿主使用须由所有者显式保留/恢复同一逻辑身份，不能自动合并两套个人或项目记忆。

包只带引用和检查点，不复制被引用记忆的正文。单包上限 32 KiB、16 条引用、每个清单最多 32 条、每条 512 字符、目标 2000 字符，期限最长 30 天。创建和打开均不修改正式记忆或使用计数，不执行任务、不联系模型或其他 Agent。

校验和防误改，不认证作者或授予权限。检查点是宿主报告的文本，不证明已完成；即使校验通过也作为数据处理。引用变化、删除、过期或依赖失效必须显示需复核，不能显示旧值为当前真值。外范围和缺失引用均返回不可用，不泄露另一范围的内容。

同一进程库实例的 SDK 调用方负责自己的 reload/persist；Agent 通道沿用每次调用刷新。已删除后逐字恢复相同版本内容并不由本包追踪其完整历史；校验的是当前状态，不是不可撤销的事件账本。

验证覆盖无副作用、原文语言、篡改、输入预算、旧修订、依赖更正、跨范围、过期、独立进程/文件恢复、只读 MCP 以及所有者 CLI。真实宿主模型接续另行验收，不由协议检查替代。
