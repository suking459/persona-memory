# Independent-policy migration

Applies to the 1.5.0 policy replacement; npm 1.0.0 retains historical behavior. See the [origin review](1.5-ORIGIN-REVIEW.md) and [prior specification](1.5-INDEPENDENT-POLICY-SPEC.md).

## Changed defaults

Default text no longer infers emotion, health, workload or good news, and no fixed relationship tone is generated. TAG_RULES is an immutable empty array. TIERS retains five numeric bands; tier returns band-0 through band-4 and hint is empty. Callers relying on old names/advice must migrate. This is not complete backward compatibility.

SCORE_RULES praise/insult/pat fields default to zero for type compatibility without word-list triggers. Explicit mention/reply/direct interactions can still score, using stable reason codes; these numbers do not prove intimacy or trust.

Trusted SDK callers can supply `affinityDelta`; Generic/HTTP input preserves it. This does not authenticate the caller or independently verify a fact. Keep host authorization. Other framework bridges do not extract it automatically from model responses. Scoped Agent access remains proposal/separate review and gains no social-write/admin authority from this option.

```js
const pm=new PersonaMemory();
pm.ingest({chatId:'example-room',userId:'example-person',
  text:'Synthetic host-assessed interaction',eventId:'actual-host-event',affinityDelta:0});
```

Explicit zero is neutral and does not add ordinary-interaction points. Positive/negative deltas obey per-message caps; positive totals also obey daily allowance. Use real evidence and application context, not arbitrary model self-scores. Business facts belong in typed records/review.

## Custom rules and stored data

Custom extraRules retains bounded literal matching and negation/quote/subject checks. For example:

```js
const pm=new PersonaMemory({config:{extraRules:{
  release:{words:['deployment window'],advice:'Ask the host to verify the release schedule.'}
}}});
```

Hosts can also set confirmed tags. Prefer candidate review for inferred typed memory. Do not copy unknown-source word lists to restore the old defaults.

The policy replacement itself did not change schema 6 semantics. Existing scores, original tags, evidence, counts, short/long-term state and formal records are retained. Removing expressions from distributed source does not authorize deleting user data. Later local schema changes follow their own migration rules.

New style candidates use Unicode words, at most once/word/message; scan at most 4096 UTF-16 units and collect at most 128 valid distinct words. Old 2–4-character windows are not regenerated. Statistics are not personality diagnoses; old stored fragments remain readable and are not automatically erased.

Back up full data and old code, test migration in isolation and roll back using the old version with its pre-upgrade backup. See [recovery](storage-backup.md).

## Version decision

On 2026-11-02 the owner explicitly selected stable 1.5.0 with incompatible-default and bounded-origin-review disclosures. This selection does not make the changes a backward-compatible minor update. Projects relying on old defaults should pin 1.0.0 or migrate explicitly rather than assume an unchecked ^1.0.0 upgrade is safe. Internal 1.6–1.9 milestones remain local; 2.0 requires separate complete validation and release approval.
