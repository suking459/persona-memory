# 独立策略候选的行为迁移

本地内部 1.5 节点，未发布。此页适用于本批独立策略替换，不能用公开 npm 1.0.0 重现。[来源复核](1.5-ORIGIN-REVIEW.md) / [实施前规格](1.5-INDEPENDENT-POLICY-SPEC.md)。

## 改变了什么

默认不再靠文字猜情绪、健康、忙碌或喜讯，也不生成固定亲疏口吻。TAG_RULES 是只读空数组；TIERS 保留五段数值边界，tier 返回 band-0 至 band-4，hint 为空。使用中文档名或旧 advice 文本做判断的调用方需要修改；这不是完全向后兼容。

SCORE_RULES 中旧 praise/insult/pat 字段默认 0，仅保留类型兼容，不再触发文本词表。普通 @、引用、明确指向仍可计交互分，原因代码为 mention/reply/direct；这些数值不证明亲密或信任。

宿主 SDK 可明确提交 affinityDelta，Generic/HTTP 输入保留该字段。它不是自动核实的事实，也不证明提出者身份；保留宿主自己的权限策略。其他框架桥接不自动从模型回答提取该值，必要时由宿主先调用 SDK。新的 scoped Agent 通道仍走候选/独立审阅，不因此开放关系写入或管理员权限。

~~~js
const pm = new PersonaMemory();
pm.ingest({
  chatId: 'example-room', userId: 'example-person',
  text: 'Synthetic host-assessed interaction',
  eventId: 'actual-host-event', affinityDelta: 0,
});
~~~

明确 0 就是中性，不再额外加普通互动分；正负值都受单条上限限制，总正分仍受每日额度。宿主应先确定真实证据与场景，不将模型随意自评分当作用户事实。业务事实优先使用有类型记录和候选审阅。

## 自定义规则和标签

用户自己的 extraRules 仍支持有界字面匹配及原有否定/引号/主体筛选。示例是独立编写的业务规则，不提供旧词表拷贝：

~~~js
const pm = new PersonaMemory({
  config: {
    extraRules: {
      release: { words: ['部署窗口'], advice: '由宿主核对发布安排' },
    },
  },
});
~~~

也可由宿主在确认内容后使用 setTag；通用记忆建议使用 memory_propose 与独立所有者审阅。不要为了恢复默认表现从来源不明插件复制整组词表或建议。

## 原数据与风格

schema 6 和旧 schema 读取方式不因本次改变。保留原关系数值、旧标签原文、证据、计数、短期/长期状态和正式记录；不把当前文件中的风险表达删除扩张成自动删除用户存储数据。

新风格候选由 Unicode 分词得到，每词每消息至多一次；只扫描前 4096 个 UTF-16 单元、最多收集 128 个有效不同词，不再从 2–4 字滑窗拼碎片。统计不是人格结论。旧 catch 数据仍可读，可能含旧片段；不会擅自清除。

升级前保留完整备份及原版本；若依赖旧默认行为，先在隔离项目验证，不直接覆盖日常环境。回退用原版本与升级前备份，不把新写数据强交给旧代码。参考 [备份恢复](storage-backup.md)。

## 版本约束

当前继续沿用内部 1.5.0-dev.0 作为工作节点。是否以主版本或独立兼容范围发布，需要在实际发布前确定；不把不兼容默认变化伪装成普通小修。版权草案批准、行为迁移和公开发布是不同决定，本批不自动执行后两者。
