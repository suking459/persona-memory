# 2.0 host and model trial protocol

Use the same candidate package, host build, model revision, provider settings, instructions, task wording, tool permissions and seed history within each comparison. Use synthetic histories. Where an isolated native memory setting is unavailable, record that arm as unavailable and keep it out of the comparison. Enable model calls only with the operator's authorization.

## Conditions

| Condition | Native memory | persona-memory | Available evidence |
| --- | --- | --- | --- |
| Disabled | Off | Off | Task instructions and current user turn |
| Native | On | Off | Same permitted history represented using native features |
| persona-memory | Off | On | Same permitted history as approved scoped records |
| Coexistence | On | On | Same total history with disjoint fact ownership and explicit references |

Before starting, record the host/model versions, candidate SHA-256, input and grading digests, case IDs, arm order and number of repetitions. Prepare one fresh history, memory directory and native configuration per arm. Preserve settings across restarts within an arm, and never reuse those directories across arms. Keep active project instructions enabled in every condition. Test using the real supported store in the native arm.

## Cases and grading

| Case | Expected observation |
| --- | --- |
| Current project constraint | The answer follows the current owner rule even when the old recalled value conflicts. |
| Two-source task | The rendered payload has both approved sources and the answer uses both facts. |
| Multilingual correction | A new process uses the corrected value, preserves source spelling and ignores the superseded value. |
| Pending and withdrawn memories | The answer uses neither a pending candidate nor an expired, forgotten or revoked record. |
| Cross-project request | Data from the ungranted scope stays out of the tool result, rendered context and answer. |
| Consolidation fidelity | The drafted summary, approved record and answer preserve distinct speakers, dates, conditions and negation. |
| Character work boundary | With identical work inputs, neutral and opposed characters produce identical work-handler payloads. The casual-only handler receives the expected expression state. |

Reserve at least one unseen task for each measured behavior before changing policies. Include both expected lexical matches and paraphrases. Repeat the same case with each eligible condition and alternate their execution order. Preserve missing/error rows instead of replacing them with successful repeats. Count successful tool completion, complete rendered evidence, answer correctness, abstention and scope violations separately. Blind-grade answers where possible and keep disagreements as an explicit count. A privacy or permissions violation fails that host trial. Model calls are stopped at a predeclared budget.

Record latency and provider-reported tokens after each completed turn. Mark unavailable measurements explicitly. Retain raw prompts, outputs and traces only in the private test directory. Report independent denominators and paired case deltas, including exclusions and their causes. Use the existing [measurement commands](measurement-maintenance.md) for matched two-arm scalar comparisons. A four-arm report can present the native, persona-memory and coexistence conditions against the same disabled cases.

The [offline evaluation](long-term-evaluation.md) checks required evidence and negative controls. The model trial adds evidence about tool choices, language behavior and answer quality on the recorded host/model pair.
