# 1.1 第一批接入改进与复核

日期：2026-11-01；本地开发版 1.1.0-dev.0。未发布，未修改 v1.0.0 标签和资产。

## 解决的问题

1.0 的 MCP 只有通用查询与关系消息记录，没有围绕实际 Agent 使用的完整候选/审阅路径，也不能只靠模型传主体当作权限边界。

新增独立 adapters/agent 入口：启动时固定主体和持久化目录；read/capture/review 分层；正式记录与候选分离；更正绑定当前头，陈旧审阅拒绝；遗忘检查范围与当前修订；只有本连接创建的上下文可确认；写盘失败或其他写者冲突停止当前连接继续读写，不发假成功回执。

新增 persona-memory-connect：生成 11 类宿主配置及工作流，本机 WorkBuddy 连接器和 DSH bundle；显式的文件配置应用保留兄弟设置，撤销核对哈希；不自动更改宿主。安装产物依赖当前安装位置，尚不是便携的市场发布包。

后续多语言批次将完整套件增至 351 项，最新结果见 [多语言复核](1.1-MULTILINGUAL-BATCH.md)；以下保留首批接入检查的历史数量。

## 复核修复

复现了“已接受提案再次重试时，回执仍写 approved=false”的问题；先保存失败用例，改为报告实际候选状态，再重跑新增检查和六个 Node 组合。另验证了错误存储绑定、越权候选/遗忘、跨连接确认、并发调用、持久化失败、其他写者冲突和撤销不覆盖后续配置修改。

配置恢复记录可能包含原配置内容，只留本机；不能把接入包直接提交到公共仓库。JSONC/存在同名服务/配置后续修改等场景明确拒绝，并非自动改掉用户原有设置。文件检查和替换存在并发窗口，应用时应关闭正在编辑配置的宿主，不宣称跨应用原子事务。
